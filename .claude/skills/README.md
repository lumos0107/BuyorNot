# 살까말까 작업용 스킬

중간 과제(인공지능 프로그래밍)를 하면서 반복되는 일을 Claude Code 스킬로 만들었다. 스킬은 `.claude/skills/<이름>/SKILL.md`이고, 기계로 볼 수 있는 규칙은 같은 폴더의 `scripts/`에 둔다. Claude Code는 description을 보고 상황에 맞는 스킬을 불러 쓴다.

## 만든 스킬

| 스킬 | 언제 쓰나 | 스크립트 |
| --- | --- | --- |
| `updating-prd` | PRD에 기능·검증 사례·결정을 넣거나 고칠 때 | `check_prd_refs.py`: 버전·번호 참조·완료 기준·입력과 결과 개수 |
| `checking-ui-copy` | 사용자가 보는 문구를 넣거나 고칠 때 | `check_copy.py`: 금지어·구매 권유·옛 용어·이모지·조사 |
| `checking-privacy` | 밖으로 나가는 데이터, 서버 코드, 평가 자료를 다룰 때 | `check_privacy.py`: 서버 로그·키·전송 안내·평가 자료 출처·.gitignore |
| `tuning-prompts` | Gemini 프롬프트·설정을 고치거나 점수를 올려 달라는 요청을 받을 때 | 없음(판단 규칙) |
| `consulting-gpt` | 결정·명세·계획을 GPT(Codex CLI)와 상의하고 기록할 때 | `append_record.py`: 기록 형식·번호 중복·LF |
| `adding-ai-endpoint` | 새 AI 서버 주소와 앱 연결을 만들거나 설계할 때 | 없음(틀과 범위 규칙) |
| `evaluating-ai` | AI 정확도를 재고 성적표(F43) 숫자를 만들 때 | 없음(평가 스크립트는 `eval/`) |
| `checking-before-commit` | 커밋하기 직전 | `check_all.py`: 금지 파일·CR·문구·개인정보·PRD·TODO 검사 + 전체 테스트·린트·타입 |
| `writing-tests-from-spec` | PRD 검증 사례를 테스트로 옮길 때 | 없음 |
| `updating-devlog` | 작업이 끝나 DEVLOG·README를 남길 때 | 없음 |
| `syncing-todo` | PRD·계획이 바뀌었거나 작업이 끝났을 때 TODO 맞추기 | `check_todo.py`: 기준 버전·기능·계획 작업 수·완료 해시 · `mark_done.py`: 작업 한 줄 완료 표시(2026-10-30 추가, GPT 46번) |
| `testing-ai-screens` | AI 서버를 부르는 화면의 테스트를 쓰거나 리뷰할 때(2026-10-30 구현 중 추가, GPT 46번) | 없음(서버 흉내·늦은 응답·숨은 화면 포커스·미리보기 해제·60초 규칙) |
| `applying-ai-results` | AI가 읽은 값을 사용자가 고칠 수 있는 칸·확인 상자에 넣는 코드를 짜거나 리뷰할 때(2026-10-30 구현 중 추가, GPT 47번) | 없음(무효화 경로·채우기 규칙·지어낸 값·확인 문장·포커스 규칙) |

## 만드는 방법

스킬 작성 지침(superpowers:writing-skills)대로 했다.

1. **기준 시험**: 스킬 없이 Sonnet 에이전트에게 실제와 같은 일을 시켰다. 일부러 문제를 넣은 화면 diff, 문제가 있는 서버 초안, "발표가 내일이니 점수를 올려 달라"는 요청, PRD에 새 기능 넣기.
2. **스킬 작성**: 기준 시험에서 에이전트가 규칙을 찾느라 쓴 곳(PRD·계획·기록)을 한곳에 모으고, 기계로 볼 수 있는 규칙은 스크립트로 바꿨다.
3. **같은 일을 스킬과 함께 다시** 시켰다.
4. **GPT 상의**(검토 기록 42번·44번)로 빠진 규칙·과한 규칙·스크립트 오탐을 고쳤다.

## 시험 결과

### 첫 묶음 (2026-10-29, 과제마다 1회씩 비교)

| 스킬 | 결과(스킬 없이 → 함께) | 토큰 | 시간 | 도구 호출 |
| --- | --- | --- | --- | --- |
| 화면 문구 점검 | 넣은 문제 5개 모두 → 5개 모두 + 빠진 문장 | 약 8.2만 → 6.1만 | 68초 → 37초 | 8 → 7 |
| 개인정보 점검 | 넣은 문제 모두 → 모두 | 약 7.9만 → 5.2만 | 97초 → 57초 | 12 → 6 |
| 프롬프트 고치기 | 누출 규칙을 지킴 → 지킴 + 과잉 교정 확인 | 약 9.1만 → 6.9만 | 147초 → 84초 | 11 → 9 |
| PRD 고치기 | 번호 참조까지 맞춤 → 맞춤 + 제작자 확인 전 표시 | 약 15.3만 → 11.9만 | 263초 → 216초 | 22 → 28 |

- **스킬 없이도 결과는 맞았다.** 저장소의 PRD·계획에 규칙이 이미 적혀 있어 에이전트가 찾아 읽었기 때문이다. 그래서 이 스킬들은 "못 하던 일을 하게 한다"가 아니라 "흩어진 규칙을 한곳에 모으고, 기계 검사와 사람 판단을 나누고, 제작자의 결정권과 평가 이력을 지키게 한다"는 데 값이 있다.
- 합계로 토큰은 약 26%, 시간은 약 31% 줄었다. 도구 호출은 53번 → 50번이고, PRD 고치기는 스크립트를 여러 번 돌려 오히려 늘었다.

- 합계(반올림 전 측정값을 더함): 토큰 약 75.6만 → 60.7만(약 20% 감소), 시간 1,009초 → 603초(약 40% 감소), 도구 호출 106번 → 74번.
- 감소의 대부분은 '새 AI 기능 틀'에서 나왔다. 이것은 같은 일을 더 싸게 한 것이 아니라, 스킬이 범위를 정해 줘서 **산출을 줄이고 멈춘** 효과다. 그것을 빼면 토큰 감소는 약 11.5%다.
- 명세→테스트와 DEVLOG는 토큰은 조금 줄었지만 시간은 각각 6초·1초 늘었고, 명세→테스트는 도구 호출도 1번 늘었다.
- 첫 묶음과 마찬가지로 스킬 없이도 대부분 결과는 맞았다. 차이는 실행 실수(GPT 출력 버림)를 막고, 범위를 넘는 작업(기능 전체 설계, README 발표 문단 수정)을 멈추게 하고, 저장소의 형식 약속(테스트 이름, TODO 작업 번호)을 지키게 한 데 있다.


### 구현 중 추가 (2026-10-30, 과제마다 1회씩 비교)

구현(계획 ai-stage1)을 작업마다 서브에이전트로 진행하다가 반복되는 일을 GPT와 상의(46번)해 더했다.

| 스킬·스크립트 | 결과(스킬 없이 → 함께) | 토큰 | 시간 | 도구 호출 |
| --- | --- | --- | --- | --- |
| `testing-ai-screens` (가격표 사진 탭의 실패하는 화면 테스트 쓰기) | 테스트 40개, 일부러 넣은 버그 18개 중 16개를 잡고 숨은 화면 포커스 버그는 못 잡음 → 51개, 22개 중 20개, 숨은 화면 포커스(`focus()` 호출 감시)·등록 안 된 서버 주소·차례 응답 소진까지 잡음 | 약 26.9만 → 27.9만 | 1,151초 → 1,070초 | 67 → 81 |
| `applying-ai-results` (2단계 캡처 치수 읽기 화면의 구현 설계만, 코드 없음) | 무효화 통합·취소 뒤 포커스·문장 다시 만들기·기준 정리는 스스로 함, 늦은 실패·`finally`가 새 상태를 지우지 않게 하는 규칙과 공용 문구 모듈은 빠짐 → 둘 다 들어가고 언마운트·미리보기 해제가 더 자세해짐 | 약 14.3만 → 14.6만 | 318초 → 369초 | 33 → 29 |
| `syncing-todo/mark_done.py` | 작업마다 총괄이 손으로 TODO 줄을 고치던 것 → 한 줄만 고치고 애매하면 거부 | — | — | — |

- `testing-ai-screens`는 비용을 줄이지 않았다. 두 시험 모두 에이전트가 시키지 않은 임시 구현까지 만들어 돌려 봤기 때문이다. 값은 테스트가 더 많은 버그를 잡게 한 데 있다. 기준 시험이 스스로 찾은 함정(가짜 타이머와 `userEvent`가 함께 멈춤, `afterEach` 순서)도 스킬에 옮겼다.
- `applying-ai-results`는 Task 10·11 리뷰에서 실제로 나온 판단(판정 R8·R9, 취소 뒤 포커스)을 모은 것이다. 설계 시험의 차이는 작고(늦은 실패 처리·공용 문구), 실제 효과는 말로 담기(14-14)와 캡처 치수 읽기 구현에서 확인한다(GPT 47번).
- `mark_done.py`는 TODO 복사본으로 7가지 경우(미리 보기, 없는 해시, 같은 해시 재실행, 다른 해시, 없는 작업, T1과 T10 구분, 실제 변경)를 시험했다.

- **한계**: 과제마다 1회만 비교했다. 같은 초기 저장소 상태·산출 범위·모델 설정으로 3~5회 반복하고 실행 순서를 섞어야 일반적인 효과라고 말할 수 있다. 기준 시험 중 일부는 먼저 만든 스킬 4개가 저장소에 있는 상태에서 돌아 그 스킬을 읽기도 했다. 스크립트는 정해진 낱말과 형식만 보므로 동의어·조합된 문장·내용의 옳고 그름은 사람이 본다.
