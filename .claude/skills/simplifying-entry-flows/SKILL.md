# 입력 부담을 줄이는 흐름

목표는 사용자가 지금 하려는 한 행동을 빨리 끝내게 하는 것이다. 새 화면을 만들기 전에 기존 입력·저장·요약에서 같은 행동을 이미 하는 곳을 찾는다.

## 새 입력 흐름

1. 현재 필드를 필수·선택으로 나누고, 각각 어디에 저장되어 어떤 결과에 쓰이는지 적는다. 처음에 필요한 값만 보이고 나중에 적어도 되는 값은 그 값이 필요한 시점에 묻는다.
2. 생략한 값은 정해진 기본값이나 명시적인 ‘아직 적지 않음’으로 다룬다. 이유·가격·절약액을 지어내지 않는다. 기본값이 결정 시점이나 금액에 영향을 주면 저장 전에 화면에 보인다.
3. 접힌 곳에 오류가 생기면 펼쳐서 오류를 보이고 그 입력으로 포커스를 옮긴다. 접고 다시 열어도 작성 중인 값은 남긴다. 다른 탭이 먼저 저장해서 반영되지 않았다면 폼을 비우거나 성공 안내를 보이지 않는다.
4. 저장 형식을 바꿀 때는 옛 기록·백업·수정·결정·회고가 생략한 값과 함께 안전하게 동작하는지 확인한다. 비어 있는 값을 실제로 입력한 이유나 실제 절약액처럼 표시하지 않는다.

## 기존 기록을 모아 보여 주는 화면

- 입력을 새로 받지 않고 이미 저장한 기록에서 행동할 날짜와 대상만 읽는다. 같은 행동이 두 곳에 보이면 원래 기록으로 이동하는 길을 제공하고, 계산을 두 군데에서 따로 정의하지 않는다.
- 날짜가 지난 항목·오늘 항목·앞으로 올 항목의 경계를 명세한다. 완료·해지·반품·만료된 기록을 아직 할 일처럼 보이지 않는다.
- 작은 화면의 첫 화면에는 한눈에 읽을 수 있는 요약을 두고, 전체 기록과 설명은 원래 화면에서 본다.

## 이 저장소에서 확인할 것

제작자에게 승인된 동작을 `updating-prd`로 먼저 적고 `writing-tests-from-spec`에 따라 실패하는 테스트를 확인한다. 화면 문장은 `checking-ui-copy`, 단계와 기록은 `syncing-todo`·`updating-devlog`, 커밋은 `checking-before-commit`을 따른다. 폭 360px에서 가로 넘침, 키보드 포커스, 접힘 상태, 기존 백업을 확인한다. 이 스킬을 썼다는 말은 실제로 위 필드 목록·날짜 경계·회귀 검사를 적용한 작업에만 남긴다.
