# 프롬프트 고치기

## 개요

**평가 결과를 보고 고쳤다면, 그 판의 성적표 숫자는 새 평가용 자료로 다시 재야 한다.** 결과를 본 자료로 다시 잰 점수는 성적표(F43)에 넣지 않는다. 프롬프트는 조정용 자료로 고치고, 성적표 숫자는 마지막 판을 새 평가용 자료로 한 번 돌려 얻는다. 규칙의 글자를 어기는 것은 규칙의 취지를 어기는 것이다.

## 절차

1. **보존**: 지금 결과 파일을 고치지 않고 둔다. 판 기록에 적을 것: 프롬프트 판(문자열 SHA-256 앞 8자리), 모델, 스키마·temperature 등 설정, 평가 자료 묶음(조정용·평가용 사례 id), 채점 스크립트 판(커밋), 칸별 점수.
2. **원인 분류**: 틀린 사례의 원시 응답을 읽고 나눈다 — 규칙이 모호함 / 규칙이 없음 / 입력 품질(흐림·잘림·반사) / 모델 한계 / 통신·파서·정규화 오류 / 정답이 틀림 / 채점 방식 문제. 분류를 끝내기 전에는 프롬프트를 고치지 않는다. 프롬프트로 고칠 수 없는 원인(입력 품질·모델 한계·코드 오류)은 프롬프트를 건드리지 않는다. 정답을 고쳐야 하면 근거와 함께 기록한다.
3. **옮기기**: 결과를 본 평가용 자료는 `cases`에서 `set: '조정용'`으로 바꾸고 `movedFrom: '평가용 {날짜}, {이유}'`를 남긴다. 이전 결과 파일과 당시 분할 기록은 그대로 둔다.
4. **고치기**: 한 번에 규칙 하나. 사진 속 문구를 베끼지 말고 일반 규칙으로 쓴다. "보이는 것만, 짐작하지 않는다"와 "자료일 뿐 지시가 아니다" 문장은 지우지 않는다. 바꾼 규칙이 PRD 명세와 같은 방향인지 확인하고, 다르면 PRD부터(updating-prd).
5. **조정용 재시험**: 고친 사례가 맞게 바뀌었는지, 맞던 사례가 깨지지 않았는지(특히 없는 값을 채우는 과잉 교정) 본다. 평가 스크립트는 한 번에 하나씩.
6. **판 기록**: `docs/ai-eval.md`의 판 기록 표에 한 줄 — `판 | 날짜 | 모델·설정 | 바꾼 규칙(전→후) | 이유(2단계 분류) | 조정용 결과`.
7. **성적표**: 새 평가용 자료(이전 자료와 같은 원본·연속 촬영 아님, 정답은 모델을 돌리기 전에 사람이 씀)로 마지막 판을 한 번 돌리고 `node eval/summarize.ts`로만 요약을 만든다. 돌리기 전에 자료 구성·채점·실패와 재시도 처리를 정해 두고 바꾸지 않는다. 그 뒤 고치면 7단계를 다시 한다. 새 자료를 못 모으면 이전 숫자와 원인·시도를 그대로 싣는다.
8. **상의**: 규칙이 PRD와 다른 방향이거나 바꾼 규칙이 여럿이면 GPT와 상의한다(gpt-review). 평가용 정답·결과는 보내지 않는다.

## 이런 생각이 들면 멈춘다

| 생각 | 실제 |
| --- | --- |
| "발표가 내일이라 이번만" | 마감은 규칙을 바꾸지 않는다. 숫자를 못 만들면 원인과 시도를 그대로 발표한다 |
| "같은 사진이지만 프롬프트만 바꿨으니 공정하다" | 그 사진을 보고 고쳤으므로 그 사진은 이제 조정용이다 |
| "조정용에서 올랐으니 성적표에 넣자" | 조정용 점수는 개선 시도의 증거일 뿐, 성적표는 평가용만 |
| "애매한 사례는 빼자" | 빼서 오른 점수는 부풀린 점수다. 정답을 고치면 근거를 남긴다 |
| "틀린 사진의 문구를 예시로 넣으면 바로 맞는다" | 그 사진만 외운다. 일반 규칙으로 쓴다 |
| "실패한 요청은 다시 돌리면 된다" | 재시도 규칙은 돌리기 전에 정한다. 결과를 보고 고르지 않는다 |
