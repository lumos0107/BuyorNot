# AI 결과를 폼에 넣기

## 개요

AI가 읽은 값은 제안이다. 사용자가 고칠 수 있고, 읽는 사이에 화면이 바뀐다. 이 스킬은 구현이 지켜야 할 상태 규칙이다(시험 방법은 testing-ai-screens). 규칙의 세부 값(어느 칸을 덮어쓰나, 포커스는 어디로)은 기능마다 다르므로 **PRD 기능 절에서 가져오고 기능끼리 섞지 않는다.**

## 규칙

1. **무효화 경로는 하나.** 결과를 무효로 만드는 모든 동작(새 사진·녹음, 취소, 고른 항목 바꿈, 결과가 덮어쓸 칸 고침, 그 물건 결정·카드 접기, 화면이 사라짐)이 같은 함수로 앞 요청을 끊고 결과를 지운다. 요청마다 번호를 두고, 비동기 뒤에는 "아직 최신 요청인가"를 다시 본다. **성공만이 아니라 오류·`finally`도** 최신 요청일 때만 상태를 바꾼다(늦은 실패가 새 읽기의 '읽는 중'을 지우지 않게). 비동기 뒤 판단은 렌더 때 값이 아닌 ref로 한다.
2. **채우기 규칙은 PRD 그대로.** 실제로 셋이 다르다: 빈 칸만 채우고 적어 둔 칸은 두며 그 칸 이름을 알림(F31·F33) / 모르는 값은 그 칸을 비움(F32) / 모름인 칸은 지금 값을 지운다고 누르기 전에 알림(F44). 빈 문자열·`null`·0을 구분한다(0은 값이다).
3. **지어낸 값에는 표시를 단다.** 읽지 않고 계산용으로 넣은 값(예: 개수 null + 용량 있음 → 개수 1)은 표시(`countAssumed` 같은 플래그)와 함께 들고 다니고, 화면 문장에도 지어낸 값임을 밝힌다. 그 값의 전제가 사라지면(사용자가 단위 '개'를 골라 용량이 비워짐) 함께 지운다. 안 그러면 오류 없이 지어낸 결과가 나온다.
4. **확인 문장은 한 함수에서.** 처음 표시와, 사용자가 확인 상자에서 고른 값(단위 등)으로 다시 그릴 때가 같은 순수 함수를 쓴다. 고른 뒤에도 '모름'이 남아 화면끼리 어긋나지 않게.
5. **다음 단계에는 고친 값.** 다음 요청·담기·저장은 사용자가 고친 칸 값으로 만든다. 고친 칸에 딸린 파생 값도 PRD대로 정리한다(포장 표기를 고치면 보낼 개당 용량·단위는 null, 읽은 치수의 기준은 칸을 고치면 저장하지 않음). PRD에 없는 파생 값 처리(예: 상품명을 고쳤을 때 읽은 브랜드)는 지어내지 말고 판정 대기로 보고한다.
6. **포커스.** 채운 뒤에는 기능 절이 정한 칸(보통 첫 오류 칸, 없으면 정해진 칸). 취소·닫기 뒤에는 시작 버튼으로 돌아간다(버튼이 사라지는 구조면 다시 그려진 버튼으로). 화면이 숨겨져 있거나 사용자가 그 흐름 밖의 칸에 적는 중이면 옮기지 않는다.
7. **자원.** 미리보기 주소는 보일 때 만들고 사라지면 해제한다. 언마운트하면 요청을 끊는다. 녹음 트랙은 모든 끝 경로에서 멈춘다.
8. **문구.** 화면 문장은 PRD 따옴표 그대로, 공용 문구는 `src/ai/messages.ts` 등 한 곳에서 가져온다. PRD에 없는 문구가 필요하면 지어내지 않고 가정 주석을 남겨 총괄 판정을 받는다.

## 기능마다 PRD에서 확인할 것

| 항목 | 질문 |
| --- | --- |
| 무효화 동작 | 어떤 동작이 앞 요청을 끊나? |
| 채우기 | 빈 칸만 / 모르는 값은 비움 / 모름은 지움(미리 알림)? |
| 지어낸 값 | 계산용으로 넣는 값과 그 전제는? |
| 확인 문장 | 무엇을 보이고 사용자 선택 뒤 어떻게 바뀌나? |
| 파생 값 | 칸을 고치면 함께 비우거나 저장하지 않는 값은? |
| 포커스 | 채운 뒤·취소 뒤·숨은 화면 |

## 실제로 생긴 일 (2026-10-30 구현)

- 계획이 정한 "(단위 모름)"이 단위를 고른 뒤에도 남음 → 규칙 4 (판정 R8).
- 단위 '개'를 고르자 계산용 개수 1이 남아 "1개당 4,500원" → 규칙 3 (판정 R9).
- 취소 버튼이 사라지며 포커스를 잃음 → 규칙 6.
- 담기가 고친 값을 쓰는지 고정한 테스트가 없었음 → 규칙 5를 테스트로도.
