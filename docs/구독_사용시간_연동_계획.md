# 구독 사용량 연동 계획

작성일: 2026-10-11 · 관련 요구사항: [PRD](../PRD.md) F16 구독 사용량(예시)

구독을 끊을지 판단하려면 "얼마나 쓰는지"가 필요하다. 이 문서는 지금 웹사이트가 보여주는 예시 사용량과, 실제 사용량을 가져오는 방법과 순서를 정리한다.

## 1. 지금 상태 (웹사이트)

- 예시 구독에만 예시 숫자를 보여준다. 사용자가 직접 넣은 구독에는 예시 숫자를 보여주지 않는다(가짜 숫자가 실제처럼 보이지 않게).
- 모든 구독 카드에 "오늘 썼어요" 버튼이 있다(2026-10-11 추가, 4장 2단계). 사용한 날에 하루 한 번 누르면(다시 누르면 취소) 그날을 기록해 "사용량(직접 기록): 최근 30일 중 3일 사용 · 쓴 날 하루에 약 4,500원"처럼 사용한 날 수로 보여주고, 기록이 있으면 예시 숫자 대신 이것을 쓴다. 하루에 여러 번 써도 1일로 센다.
- 사용량은 두 종류로 본다.

| 구독 종류 | 사용량 | 카드에 보이는 문장 (예시) |
| --- | --- | --- |
| OTT·음악 | 최근 30일 사용 시간 | 최근 30일 18시간 · 1시간에 약 750원 |
| 배달·쇼핑 멤버십 | 최근 30일 사용 횟수(주문 등) | 최근 30일 1번 사용 · 1번에 약 7,890원 |
| 클라우드 저장공간 등 | 시간·횟수로 보기 어려움 | 표시하지 않음 |

- 한 번에 드는 돈 = 월 요금(연 구독은 ÷12) ÷ 사용 시간(시간) 또는 사용 횟수, 10원 단위 반올림.
- 저장 필드: `exampleUsageMinutes`(분), `exampleUseCount`(횟수) 중 하나(예시), `useDates`(직접 기록한 날, 최근 90일만 보관).

## 2. 웹사이트에서 바로 가져올 수 없는 이유

브라우저는 보안상 다른 앱의 사용 기록이나 휴대폰의 스크린 타임에 접근할 수 없다. 운영체제에서 다른 앱의 사용 기록을 자동으로 가져오려면 휴대폰 앱(네이티브 앱) 연동이 필요하다. 기록 파일 올리기와 직접 기록은 지금처럼 웹에서도 할 수 있다(3장).

## 3. 방법별 정리

| 방법 | 가져올 수 있는 것 | 제약 |
| --- | --- | --- |
| 안드로이드 앱 + UsageStatsManager | 앱별 사용 시간(일·주 단위), 앱을 연 횟수 | 사용자가 설정의 '사용 정보 접근'에서 직접 허용해야 한다. 스토어 배포 시 정책 확인 필요 |
| iOS 스크린 타임 API (FamilyControls·DeviceActivity) | 애플이 승인한 앱의 '보고서 화면' 안에서 사용 시간 표시 | Family Controls 사용 승인을 애플에 따로 신청해야 한다(수 주 걸린 사례). 사용 시간은 보고서 확장 안에서만 보여줄 수 있고, 숫자를 앱의 계산이나 저장으로 꺼낼 수 없다 |
| 서비스에서 받은 기록 파일 올리기 | 넷플릭스 시청 기록(CSV), 유튜브 시청 기록(구글 테이크아웃) | 서비스마다 형식이 다르고, 사용자가 직접 내려받아야 한다. 파일은 기기 안에서만 읽는다 |
| 앱에서 직접 기록 ("오늘 썼어요") | 모든 구독의 사용한 날 수 | 사용한 날에 하루 한 번 눌러야 하고, 같은 날 여러 번 쓴 것은 구분하지 않는다 |

배달·쇼핑 멤버십의 주문 횟수는 스크린 타임으로도 알 수 없다. 앱을 연 횟수로 대신 볼 수는 있지만 주문 횟수와는 다르다. 직접 기록("오늘 썼어요")도 사용한 날 수라서 주문 횟수는 알 수 없고, 하루에 여러 번 주문해도 1일로 센다.

## 4. 단계 계획

1. **지금 (완료)**: 예시 숫자로 화면과 계산(1시간·1번에 드는 돈)을 만든다. 실제 숫자가 들어올 자리를 미리 확인하는 단계다.
2. **웹에서 직접 적기 (완료, 2026-10-11 F25)**: 구독 카드의 "사용량 적기"로 스크린 타임(디지털 웰빙)에서 본 최근 30일 사용 시간이나 배달·쇼핑 앱 주문 내역에서 센 횟수를 한 달에 한 번 적는다. 적은 날을 함께 저장하고 30일이 지나면 다시 적으라고 알린다. 적은 사용량이 있으면 예시와 오늘 썼어요보다 먼저 보여준다. 배달 횟수는 자동으로 알 방법이 없어(배달 앱의 공개 API 없음) 앱으로 만든 뒤에도 이 방법을 기본으로 한다.
2-1. **웹에서 직접 기록 (완료)**: 구독 카드의 "오늘 썼어요"로 사용한 날을 쌓아 최근 30일 중 사용한 날 수와 쓴 날 하루에 드는 돈을 계산한다. 마지막 사용일과 해지 후보 판정에도 반영한다. 자동 연동 전까지의 대안이며 모든 구독에 쓸 수 있다.
3. **안드로이드 앱**: 지금 웹앱을 앱으로 감싸고(예: Capacitor), UsageStatsManager로 구독 앱별 최근 30일 사용 시간을 읽어 예시 숫자 자리에 넣는다.
   - 구독과 앱의 연결은 사용자가 고른다(예: 넷플릭스 구독 → 넷플릭스 앱 `com.netflix.mediaclient`).
   - 권한이 없으면 지금처럼 직접 기록으로 돌아간다.
4. **iOS**: 보고서 화면으로 구독 앱의 사용 시간을 보여주는 정도만 검토한다. "1시간에 드는 돈"처럼 앱에서 계산하는 기능은 iOS에서는 어렵다.

## 5. 데이터 원칙

- 사용량은 기기 밖으로 보내지 않는다. 서버를 두지 않는 지금 구조를 유지한다.
- 자동 연동을 붙이면 예시 필드를 실제 사용량 필드와 출처(`source`: 스크린 타임·직접 기록·파일)로 바꾸고, 화면의 "(예시)"·"(직접 기록)" 표시를 출처 표시로 통일한다.
- 정확하지 않은 숫자를 실제처럼 보이게 하지 않는다. 출처가 없는 숫자에는 "예시"를 붙인다.

## 6. 연동 전에 확인할 점

- **측정 범위**: 앱 사용 시간은 그 휴대폰에서 앱이 화면에 떠 있던 시간이다. 화면을 끄고 듣는 음악, TV·PC 등 다른 기기에서 본 시간은 빠질 수 있으므로, 화면에 "이 휴대폰에서 앱을 쓴 시간"이라고 범위를 적는다.
- **집계와 보관**: 안드로이드 사용 통계는 일·주·월 같은 묶음으로 보관되고 오래된 일 단위 기록은 남지 않을 수 있다. 최근 30일을 어떤 단위로 합칠지 실제 기기에서 확인한다.
- **횟수 세는 방법**: 앱을 연 횟수는 앱이 화면 앞으로 온 순간(사용 이벤트)을 세는 방식이라, 잠깐 켰다 끈 것도 1번이 된다. 배달·쇼핑 멤버십은 직접 기록을 기본으로 한다.

- [FamilyControls distribution 승인 대기 사례 (Apple Developer Forums)](https://developer.apple.com/forums/thread/825453): 배포용 권한 승인에 시간이 걸림
