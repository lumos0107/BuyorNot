## 중단 작업 재개 기록

사용자의 재개 요청으로 29~31단계 구현을 이어갔다. 아래의 최초 복원 점검과 당시 `고칠 것` 목록은 그 시점의 기록으로 남긴다. 목록 1~3번은 이번 작업으로 해결했다. 사진 중심 첫 화면과 서버가 없을 때의 할인 비교 대체, 장보기 요리 선택 통합·부족 재료 출처·빈 상태 안내, 물건 카드의 사기 전 요약 이동과 한 종류씩 여는 상세 입력을 구현했다. 기존 시험은 필요한 화면으로 명시적으로 이동하게 고쳤다. 4~8번의 문서·제품 판단과 실제 기기 판정은 후속 검토 대상으로 남는다.

360px 브라우저 화면에서 문서 너비 345px으로 가로 넘침이 없음을 확인했다. 실제 스마트폰 사진 선택과 제작자 화면 판정은 별도 확인이 필요하다.

최종 확인: 전체 자동 테스트 1990/1990, lint 경고 없음, 타입 검사, 배포 빌드, PRD·TODO 참조 검사 통과. 구현 커밋은 `4ac7b0d`이며 `saving`에만 로컬 저장했다. 빌드의 JS 청크 500kB 경고는 남아 있다.

기준: `saving` HEAD `3e28f0f`. [Claude 작업 인계](./Claude_작업인계_2026-11-02.md), [GPT 작업 인계](./GPT_작업인계_2026-11-02.md), [GPT 커밋 목록](./GPT_커밋목록.md), 원래 [GPT 인계](../../.superpowers/sdd/saving/GPT_인계.md), 코드·시험을 대조했다. 이 문서는 검토 기록이며 29~31단계 완료 판정이 아니다.

## 고칠 것

1. **우선: 29단계 첫 화면 변경의 회귀를 해결한다.** [App.tsx](../../src/App.tsx)에서 초기 메뉴가 물건에서 가격 비교로 바뀌어, 물건 화면을 초기 화면으로 가정한 기존 `App.*.test.tsx` 시험이 대거 실패한다. 예를 들면 [App.wishlist.test.tsx](../../src/App.wishlist.test.tsx), [App.calendar.test.tsx](../../src/App.calendar.test.tsx), [App.beforeBuy.test.tsx](../../src/App.beforeBuy.test.tsx)다. 기존 동작을 확인하는 시험에는 물건 탭을 여는 단계를 넣고, 초기 화면 자체를 검증하는 시험은 새 요구에 맞게 고친 뒤 전체 회귀를 다시 실행한다. [App.photoTag.test.tsx](../../src/App.photoTag.test.tsx)의 사진 탭 순서 기대도 옛 순서다. 29단계는 아직 완료·커밋하면 안 된다.
2. **우선: 새 AC197 시험의 요소 선택을 바로잡는다.** [App.photoHome.test.tsx](../../src/App.photoHome.test.tsx)는 `getByRole('button', { name: '가격표 사진 찍기' })`를 쓰지만, [PhotoPicker.tsx](../../src/screens/ai/PhotoPicker.tsx)는 `<label>` 안에 파일 `<input>`을 둔다. 사진 입력을 연결된 라벨로 찾는 시험으로 바꾸고 실제 선택 동작도 확인한다. 이 오류 때문에 새 시험만 실행해도 1개 실패한다.
3. **우선: 30·31단계는 설계만 있는 상태로 유지하고 범위를 결정한다.** [UX 계획](../superpowers/plans/2026-11-02-ux-p8.md)의 장보기 선택 통합과 물건 카드의 사기 전 확인은 아직 구현되지 않았다. [TODO](../../TODO.md)의 미완료 표시는 맞다. 제작자가 재개를 정하면 AC198~AC202 구현·시험과 360px 화면·키보드 확인을 진행한다.
4. **문서: 현재 백업 판과 AC 표를 맞춘다.** [backup.ts](../../src/logic/backup.ts)는 판 3을 내보내고 판 1~3을 읽는다. [PRD](../../PRD.md)의 AC99·AC116은 아직 판 2를 새 파일로 예상하고 판 3 파일을 거절한다고 적어 현재 구현과 충돌한다. 1a·1b 당시 이력은 남기되 현재 완료 기준에는 판 3과 옛 파일 호환을 명시한다.
5. **문서·판정: GPT 후기 기능을 기록에 연결한다.** [PRD](../../PRD.md) 9장의 제작자 확인 전 목록은 F75까지 있고 F76~F81이 없다. [판정표](../평가/판정표.md)는 71번/F75에서 끝난다. 25~28단계의 F76~F81과 29단계의 변경 결정을 판정표·PRD 9장에 연결한다. [PRD](../../PRD.md)의 F72·F81 목적 문장과 판정표 68번도 첫 화면을 물건 화면으로 가정하므로, 29단계가 확정되면 실제 위치에 맞춘다.
6. **문서: 이동 이후 사실을 갱신한다.** [GPT 작업 인계](./GPT_작업인계_2026-11-02.md)에는 `saving`이 원격에 없고 이동 묶음에 `_개인기록`과 키가 없다고 적혀 있으나, 이후 `saving`은 `3e28f0f`까지 push됐고 이번 USB 묶음으로 Git 제외 자료도 복원했다. [README](../../README.md)의 “아직 push 전”도 이제 오래된 상태다. 날짜가 있는 당시 기록은 보존하고 현재 상태를 덧붙인다.
7. **검토: `생긴 돈`의 의미를 분명히 한다.** [SavingsScreen.tsx](../../src/screens/SavingsScreen.tsx)는 되팔기 금액(실제 입금 미확인)과 직접 적은 받은 지원금을 하나의 `생긴 돈` 합계로 보여 준다. 옮긴 돈·참은 구매·반품액은 별도이며 목표에는 옮긴 돈만 들어가는 것은 코드와 로직 시험에서 확인했다. 다만 확정 여부가 다른 되팔기와 지원금을 합치는 표현은 제작자에게 확인받고, 필요하면 각각 별도 줄로 나누는 편이 명확하다.
8. **낮은 우선순위: 개발 의존성 취약점과 빌드 크기.** `npm audit`는 `jsdom`이 쓰는 `undici@8.11.2`에 high 1건을 보고했고, `npm audit --omit=dev`는 0건이다. 잠금 파일 갱신 후 시험한다. 빌드의 JS 청크는 500 kB 경고를 넘는다.

## 확인이 남은 것

- 실제 스마트폰의 사진 선택, 360px 폭, 주요 탭 키보드 포커스, 사용자 화면 판정. 자동 시험·PC 브라우저 확인은 이를 대신하지 않는다.
- 기본 Worker는 다나와 자동 조회가 꺼진 상태다. 실제 사진의 상품·규격 일치율과 배송비 포함 결제액도 아직 평가되지 않았다. [GPT 작업 인계](./GPT_작업인계_2026-11-02.md)의 사진 한 장 시험을 정확도 검증으로 확대 해석하지 않는다.
- 사용자 결정을 기다리는 제작자 판정 칸, README 학생 서술, 29~31단계 재개, 서버 배포는 그대로 남긴다. `main`은 push하지 않았다.
