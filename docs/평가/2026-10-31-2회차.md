# 다각도 평가 2회차(평가 B) (2026-10-31)

- 대상: 브랜치 `ai-stage1` 커밋 `595974c`(개발 1회차 16-1~16-5 뒤, 자동 테스트 1503개, 서버 미배포, 실제 자료 정확도 평가 전)
- 요청: 제작자 "전체 프로세스를 2번". 평가 → 결정 → 개발 → 평가의 두 번째 평가다.
- 방법: 고정 기준 [평가기준.md](평가기준.md) 그대로. 평가 에이전트 5명(A 실제 사용자는 브라우저 360px, B 교수, C 보안·신뢰성, D 접근성·문구, E 기능 기획) → 세 관점(사용자 가치·채점 가치·비용 위험) 토론 2라운드 → GPT 상의(51번) → 결정(판정 R38). 다른 Claude 세션은 쓰지 않았다(평가자는 모두 이 세션의 서브에이전트).
- 실제 AI 호출(서버 로그 기준): 평가자 A의 가격표 읽기 2번. A가 본 치수 읽기 결과는 모의 응답이었다(아래 정정). 총괄이 정정을 확인하려고 A가 보낸 사진으로 치수 읽기를 1번 직접 불렀다.
- 원문: 같은 이름의 폴더 `2026-10-31-2회차/`(A~E 평가, R1·R2 토론). A·B·C·E 원문 머리에 P1 정정 메모를 붙였고, 로컬 절대 경로는 '(저장소 밖 임시 폴더)'·'(작업 루트)'로 바꿨다.
- 정정(평가 도중, 커밋 `4424b26`): 평가자 A가 본 "치수 읽기가 사진에 없는 치수 세 줄을 다시 냄"은 Gemini가 아니라 2단계 화면 확인(TODO 15-8)이 Playwright `page.route`로 `/api/read-size`에 넣은 모의 응답이 같은 브라우저에 남아 돌아온 것이었다. 1회차 P1도 같다. 근거는 서버 로그에 두 평가의 `POST /api/read-size`가 없음, 모의 응답 세 줄이 화면의 세 줄과 글자까지 같음, A가 보낸 사진을 서버에 직접 보내면 정답이 옴, 이렇게 셋이다. 자세한 것은 [1회차 기록](2026-10-31-1회차.md) 6장 끝.

## 5. 결정: 개발 2회차 범위(판정 R38, GPT 51번 동의)

반드시:

1. 문서: 낡은 사실(P10)을 고치고, P1 정정(P11)을 `docs/ai-eval.md`의 한 단락(날짜·근거·영향받은 판정·재발 방지)과 README 4장의 한 문장(링크)으로 모은다. 판정표에 '꼭 볼 줄'을 표시한다(I11, 판정은 제작자).
2. 서버(P6 일부): Gemini가 429를 주면 우리 서버는 `429 { error: 'upstream_limited' }`로 답하고, 앱은 "AI 사용이 제한됐어요. 나중에 다시 시도하거나 직접 입력해 주세요."를 보인다. `GEMINI_API_KEY`가 없거나 비면 Gemini를 부르지 않고 `503 disabled`로 답한다(앱 문구는 기존 그대로). 같은 IP 제한은 그대로 `429 rate_limited`. 평가 채점은 제한으로 뺀 요청 수를 채점한 요청 수와 함께 보이는 지금 방식을 유지한다.
3. F32·F44 확인 상자(P9·I8): 첫 줄을 상자의 설명(aria-describedby)으로 잇고, F32 첫 줄을 "AI가 읽은 내용: ‘…’"으로 바꾼다. 판정표 #28의 범위를 넓혀 새 줄을 만들지 않는다.
4. 회고 ①(N3 일부): 구매함으로 옮긴 직후 결정 알림에 회고를 언제부터 적을 수 있는지 사실 한 줄.
5. 스킬 규칙(P12): `testing-ai-screens`에 브라우저 확인 규칙(새 브라우저 컨텍스트에서 확인, 모의 응답은 그 확인의 `finally`에서 바로 해제하고 컨텍스트를 닫기, 실제 호출 여부는 서버의 POST 로그로 확인하고 로그가 없으면 미확인으로 기록)과 description의 Playwright·브라우저 확인 말. 고치기 전에 규칙 없이와 규칙과 함께를 비교하는 시험을 먼저 한다(writing-skills). 평가기준.md에서 이 스킬로 링크한다.

하면 좋음: 배포 계획 Task 17 보정(치수 읽기 경로, 무료 한도 숫자 빈칸, P6의 나머지), 첫 화면: 빈 목록 상자의 기존 설명 문장을 담기 폼 위로 옮기기(I3, 새 문구 없음).

## 7. 미해결

- 치수 읽기의 실제 정확도: 이 합성 캡처의 실제 기록은 3번 모두 정답이지만 한 장의 합성 캡처라 정확도가 아니다. 평가 A(1회차)와 평가 B의 A5 치수 읽기 결과는 비교에 쓰지 않는다. 평가 C에서 처음 깨끗이 잰다.
- 같은 입력에서 출력이 흔들림: temperature 0인데 같은 캡처의 text가 `x`와 `×`로, 같은 가격표의 상품명이 "…MTJV3KH/A 자급제"와 "…USB-C"로 달랐다(모두 실제 호출). 상품명은 검색어와 담기 이름으로 가므로 사용자에게는 '그때그때 다른 앱'으로 보일 수 있다. 원인과 빈도는 모른다.
- 묶음 단가 라벨(P8)을 모델이 지금 어떻게 읽는지: 평가 B는 스텁으로만 봤다.
- 가격표 읽기 숫자 칸의 같은 숫자 반복 위험: 관측 없음, `docs/ai-eval.md` 한계 그대로.
- 긴 스크롤 캡처(I12): 계산만 있고 모델 반응은 모른다.
- 확인 상자 설명 연결의 효과: 자동 테스트는 연결만 본다. 실제 스크린리더가 읽는지는 폰에서 확인하기 전까지 모른다.
- 스킬 규칙의 효과: 규칙 없이와 함께를 비교하는 시험 전이다.
