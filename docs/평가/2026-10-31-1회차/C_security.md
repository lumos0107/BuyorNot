# 평가 C: 보안·개인정보·운영 안정성 (첫 공개 배포 점검)

평가일 2026-10-31, 브랜치 `ai-stage1`(작업 트리 깨끗함). 저장소 파일은 고치지 않았다.

내가 직접 돌려 본 것: `npm test` 1465개 통과, `npx tsc -b` 통과, `check_privacy.py` OK, `wrangler deploy --dry-run`(번들 38KB, 변수 3개 확인, 배포 안 함), `git grep`·`git log --all -p`로 키 모양(`AIza`+35자) 검색(작업 트리와 전체 이력 모두 0건), 기존 `dist/index.html`의 CSP 문자열 확인, 임시 폴더에서 다나와 파싱·사진 본문 처리의 CPU 대략 측정(Node, 아래 5번).
못 한 것: 실제 Cloudflare·Gemini·다나와 호출(금지), Gemini 무료 한도 숫자 확인(이 모델의 한도는 AI Studio 화면에서만 확인 가능), 실기기 확인.

## 1) 한 줄 총평

키 보관·본문 상한·CSP·고지 설계는 무료 과제 배포로는 탄탄하지만, 인증이 없는 공개 주소에 무료 한도 하나(Gemini 키)가 걸려 있고 배포 절차에 빈틈이 있어서, "한도 소진·절차 실수로 시연 날 AI가 안 되는 것"이 가장 큰 위험이다. 아래 보완과 체크리스트를 지키면 배포해도 된다.

## 2) 잘된 점

1. **키가 새지 않는 구조**: 키는 Worker 비밀 변수와 `x-goog-api-key` 헤더에만 있다(`worker/src/gemini.ts:87`). 주소에 키를 붙이지 않고 `console` 출력도 없다(`check_privacy.py`가 막음). `.dev.vars`·`_개인기록/`·`.wrangler/`는 `.gitignore`에 있고, 전체 이력에서 개인 폴더·키 파일 경로가 한 번도 커밋되지 않았으며 개인 식별 정보(학번·이메일·내 PC 경로)도 추적 파일에서 0건이다. 공개 저장소에 80개 커밋이 올라가도 안전하다.
2. **Worker가 열린 프록시가 아니다**: 프롬프트와 응답 스키마가 서버에 고정돼 있어 임의의 질문을 Gemini에 보낼 수 없고(남용 매력이 낮음), 사진·녹음은 매직 바이트로 형식을 검사하며(`magic.ts`), 응답 값은 범위·길이를 다시 검사해 null로 바꾼다. 본문은 JSON을 풀기 전에 스트리밍으로 끊는다(`http.ts:77-98`). 허용하지 않은 출처에는 CORS 헤더를 주지 않고(`http.ts:34-43`), `Object.hasOwn`으로 경로를 검사하며, 응답은 `no-store`다. 다나와 조회는 호스트 고정·리디렉션 재검사·3MB·10초 상한이라 SSRF 여지가 없다(`danawa.ts:17-36`).
3. **CSP가 실제로 엄격하고 빌드가 실패 쪽으로 닫힌다**: `script-src 'self'`, 외부 스크립트·분석 도구 없음, `dangerouslySetInnerHTML`은 검사 스크립트가 금지한다. AI 주소가 https가 아니면 빌드를 멈추고(`csp.ts:37-45`, `vite.config.ts:22-25`), 서버 주소가 없으면 AI 버튼 자체가 안 보인다. 기존 `dist`의 CSP는 `connect-src 'self'`, `img-src 'self' blob:`로 의도대로다.
4. **다나와 기본 꺼짐과 긴급 차단이 코드에 있다**: `DANAWA_ENABLED=false`면 다나와도 Gemini도 안 부르고 링크만 준다(`lowestPrice.ts:133`). `AI_ENABLED`로 전체 503. 약관이 불확실하다는 점을 PRD가 숨기지 않고 적었다(`PRD.md:591`).
5. **사용자에게 가는 고지와 사진 처리**: 사진·녹음 안내가 버튼 바로 아래에 있고(`TagPhotoCheck.tsx:312`, `VoiceFillButton.tsx:194` 등), 사진은 1600px JPEG로 다시 그려 EXIF(위치)가 빠진다(`image.ts:1-2`). 정적 사이트(Pages)와 Worker가 분리돼 있어 Worker가 죽어도 기존 기능은 그대로다.

## 3) 문제 (가능성 × 영향 순)

### 높음

**H1. 인증 없는 공개 주소의 무료 한도 소진 (남용·우발 모두)**
- 근거: 출처 확인이 유일한 접근 통제다(`http.ts:108-109`). `Origin` 헤더는 브라우저가 아닌 클라이언트(curl, 스크립트)가 마음대로 쓸 수 있어, 학우 한 명이 개발자 도구에서 주소를 보고 반복 호출할 수 있다. IP 제한은 인스턴스 메모리라(`index.ts:13`, `rateLimit.ts:5`) 인스턴스·데이터센터가 여러 개면 사실상 느슨하고 하루 총량 제한이 없다. 한 IP가 분당 10번이면, 모델의 하루 무료 요청 한도가 N일 때 N/10분 만에 소진된다(N이 250이면 25분, 1000이면 100분. N은 AI Studio에서 확인 필요). 소진되면 날이 바뀔 때까지 모든 AI 기능이 실패한다.
- 비용 위험은 낮다: 키가 결제 없는 무료 등급이면 청구되지 않는다(`PRD.md:558`). 그래서 "돈"이 아니라 "시연 날과 채점 시기에 AI가 멈추는 것"이 영향이다. 반대로 키가 속한 구글 프로젝트에 결제가 붙어 있으면 이 위험이 곧바로 청구 위험이 된다. 배포 전 확인 1순위.
- 우발 소진도 있다: 수업에서 여럿이 동시에 눌러 보면 분당 한도에 걸린다.
- 긴급 차단(`AI_ENABLED`)은 코드에 있지만 휴대폰에서 끌 수 있는지, 재배포 때 되돌아오지 않는지는 확인된 적이 없다(아래 H2-e).

**H2. 배포 절차(계획서 Task 17)의 빈틈** (`docs/superpowers/plans/2026-10-28-ai-stage1.md:398-405`)
- a. Step 4의 확인 대상이 세 주소(사진·상품·녹음)뿐이다(`:403`). 나중에 더한 `/api/read-size`가 빠졌다. `index.ts:17-22`의 네 경로를 모두 시험해야 한다.
- b. "11번 연속은 429"를 정상 사진으로 하면 Gemini를 10번 부르고 하루 한도를 쓴다. 한도 검사는 본문 검사보다 앞이라(`http.ts:134-146`) 잘못된 본문(400이 날 JSON)으로 하면 Gemini를 안 부르고 429만 확인된다.
- c. Step 5가 운영 Worker의 `ALLOWED_ORIGINS`를 바꿨다 되돌리는 방식이다(`:404`). 보안 영향은 거의 없지만(어차피 Origin은 위조 가능) 되돌리기 누락과 재배포 실수가 걱정이다. 두 번째 Worker(예: `--name buyornot-ai-staging --var ALLOWED_ORIGINS:http://localhost:4173`)로 시험하고 지우는 편이 안전하다.
- d. `GEMINI_API_KEY`를 안 넣고 배포해도 아무 검사가 없다(`env.ts:4`, `gemini.ts:87`). 값이 `undefined`이면 모든 호출이 Gemini 400 → 앱에는 "읽지 못했어요"로만 보여 원인을 찾기 어렵다.
- e. `wrangler.jsonc`의 `vars`는 배포할 때마다 파일 값으로 덮인다(`wrangler.jsonc:5-9`). 대시보드에서 `AI_ENABLED`를 꺼도 다음 `worker:deploy`가 다시 `true`로 만들 수 있고, 대시보드에서 아예 못 고치게 잠길 수도 있다. 이 동작은 내가 확인하지 못했다. 배포 날 직접 눌러서 확인할 것.
- f. 병합 순서: `.env.production`이 없으면 AI 없는 사이트가 조용히 배포된다(안전하지만 시연 때 놀람). 반대로 스테이징 주소가 `.env.production`에 커밋되는 사고가 가능하다.
- g. README(`README.md:185`)에 "서버 배포도 이 파일도 아직 없습니다"가 남는다. 배포 뒤 고칠 것.

### 중간

**M1. Gemini 429(쿼터)가 사용자·제작자에게 구분되지 않는다**
- 근거: `gemini.ts:34-35`는 503만 `busy`로 두고 나머지 비정상 응답은 모두 `fail` → Worker 502 → 앱은 "지금은 읽지 못했어요. 직접 입력해 주세요."(`messages.ts:20-21`). 앱의 "지금은 사용이 많아요"는 우리 서버의 429에만 나온다(`client.ts:57`). AC60의 "Gemini 429" 사례도 502로 정해져 있다.
- 영향: 한도 소진이 몇 시간 이어져도 사용자는 "사진이 흐려서인가" 하고 계속 다시 찍는다(각 시도가 또 Gemini 호출). 제작자도 로그가 없어 원인 판단이 늦다. 수업에서 여럿이 동시에 시험할 때(분당 한도) 가장 흔히 만날 실패다.

**M2. 가격표 읽기의 숫자 반복 잔여 위험 (발표 핵심 경로)**
- 근거: 치수 읽기는 숫자 칸을 글자 칸으로 바꿔 고쳤지만(`readSize.ts:36-41`), 가격표 읽기는 `size`가 아직 NUMBER·`price`·`count`가 INTEGER다(`readTag.ts:30-39` 근처, `size`는 37행). `docs/ai-eval.md:209`도 같은 위험을 적어 두었고 "문제가 보이면 먼저 검토"로 보류했다. 상한 6144토큰(`readTag.ts:52`)은 반복을 막지 못하고, 문서의 속도(초당 230~460토큰)로 계산하면 13~27초 기다린 뒤 502가 난다.
- 영향: 실제 사진 정확도 평가가 아직 없어(`docs/ai-eval.md:178`) 얼마나 자주인지 모른다. 가격표 사진은 F31·F32의 시작점이라 시연에서 가장 많이 쓰인다. 반복이 생긴 요청도 한도를 쓴다.

**M3. 다나와: CPU 미측정·약관 미확정·고지 부족 (켤 때만 해당)**
- CPU: Workers 무료는 요청당 CPU 10ms가 한도라고 알고 있다(배포 날 문서에서 재확인). `parseDanawaRows`는 최대 3MB(`danawa.ts:6`) 문서에 정규식을 여섯 번 돌린다(`:156-165`). 테스트용 픽스처는 870바이트라 실제 크기·구조에서 재 본 적이 없다. 내가 임시로 만든 단순한 가짜 페이지로 Node에서 재 본 값은 1MB 약 5ms, 3MB 약 20ms(이 PC, 참고용). 실제 페이지는 더 복잡할 수 있다. 사진 요청 쪽(JSON 풀기·다시 만들기, 4.1M자)은 1ms 미만이라 문제없다.
- 약관: "사전 승낙 없이 영리 목적 복제·배포 금지"가 있고 허락은 확정되지 않았다(`PRD.md:591`). 기본 꺼짐은 올바른 선택이다. 공개 배포에서 켜지 않는 것을 권한다.
- 고지: 켜면 상품명·브랜드·규격 글이 다나와(검색어)와 Gemini(고르기 입력)로 가는데, 이를 알리는 문구는 사진 안내(`PHOTO_NOTICE`)뿐이고 "온라인 가격 확인" 근처(`TagPhotoCheck.tsx:353-410`)에 없다. 다나와가 Cloudflare 출구 IP를 막으면 `unavailable`로 끝나는 것은 설계돼 있다.
- 꺼진 상태(`status: off`)에서 발표의 핵심 문구("찍으면 온라인 가격 비교")와 실제 화면(링크만)이 어긋나지 않는지 화면 문구 확인이 필요하다.

**M4. 녹음은 실기기·실제 형식에서 확인된 적이 없다**
- 사전 시험은 TTS 음성을 변환한 파일이었고(`docs/ai-eval.md:185`: 합성 녹음은 WAV뿐), 11~36초가 걸렸다(`PRD.md:545`). 서버는 시도 하나를 40초에서 끊는다(`gemini.ts:7`). 36초가 이미 상한에 가깝고, 실패하면 남은 15초 동안 다시 시도하지 않는다(타임아웃은 재시도 대상이 아님, `gemini.ts:105`). 아이폰 사파리의 `audio/mp4`(조각난 mp4)를 Gemini가 받는지는 미확인이다. 급우 상당수가 아이폰이라 가능성이 낮지 않다. 실패해도 안전하게 "읽지 못했어요"로 끝나지만 시연 중이면 곤란하다.

**M5. 학교·통신사 공유 IP에서 분당 10번이 빡빡하다**
- IP별 10번/분(`index.ts:13`)이고 한 번의 가격표 흐름이 2요청(읽기+온라인 확인), 사진 비교는 상품마다 1요청이라 한 사람이 1분에 5번 정도 하면 끝난다. 학교 Wi-Fi가 NAT 하나로 나가면 여러 명이 합쳐서 센다. IPv6는 /64로 묶는다(`http.ts:66-72`). 값이 코드에 박혀 있어 시연 날 바꾸려면 재배포가 필요하다. 다만 실제 병목은 Gemini 분당 한도라 둘이 함께 작용한다(M1).

### 낮음

**L1. 고지 빈틈**: (a) 안내 문구가 "Google Gemini로 보내져요"뿐이고 제작자 서버(Cloudflare)를 거치고 국외로 간다는 말이 없다(`messages.ts:5-8`). (b) `.ics`에는 "처음 적은 이유"가 들어가는데(`calendar.ts:73`) 화면 설명은 구글 링크에 상품명이 간다는 말뿐이다(`WishlistScreen.tsx:774-776`). 파일을 공유 캘린더에 넣으면 이유가 보인다. (c) 위 M3의 상품명 고지. 모두 실제 위험은 작지만 공개 앱이면 한 줄씩 있는 편이 좋다.

**L2. 계정·주소 위생**: (a) 처음 배포할 때 정하는 `workers.dev` 하위 이름이 공개 번들·CSP에 그대로 들어간다. 실명·이메일 조각이 들어가지 않게. (b) 로그를 안 남긴다는 PRD 주장(`PRD.md:546`)과 달리 `wrangler.jsonc`에 `observability`가 명시돼 있지 않다. 기본값은 꺼짐으로 알지만 `"observability": {"enabled": false}`로 못박고 대시보드에서 확인할 것. (c) 같은 출처 `https://lumos0107.github.io`는 제작자의 다른 사이트(OS 문제풀이·도서관 가이드 등)도 같다. 그 사이트의 스크립트는 이 API를 부를 수 있다(영향 작음). (d) 미리보기 주소(`preview_urls`)가 기본 켜져 있을 수 있다. 끄는 것이 깔끔하다.

**L3. 잡동사니**: 저장소 루트의 `g-top.png`·`g-after.png`(10/13 화면 캡처, 해로운 내용은 없음), Actions가 태그(`@v4`)로 고정(커밋 해시 고정 아님). 읽기 권한만 주는 설정이라 위험은 작다.

| 8 | 가격표 읽기 `size`를 글자 칸으로 바꾸는 안을 시연 전에 결정. 바꾸면 프롬프트 판 해시가 바뀌므로 `docs/ai-eval.md`에 "판 기록"을 더하고 조정용 8장으로 한 번 확인(평가용은 건드리지 않음) | M |
| 9 | 녹음 시도 상한을 40초에서 50초로(예산 55초 안) 올리는 안을 검토. 또는 실기기 시간을 재 보고 결정 | S |

## 5) 추가 기능 제안 (PRD 기존 후보 F36~F42와 겹치지 않음)

1. **서버 상태 확인 `GET /api/status`와 앱의 "AI 쉬는 중" 표시** (S): 켜짐·꺼짐·다나와 상태만 알리고 Gemini는 부르지 않는다. 사진을 찍고 올린 뒤에야 "멈췄어요"를 보는 일을 막고, 배포 날 스모크 시험과 시연 직전 점검도 한 번에 된다. 이 관점에서 필요한 이유: 운영 중 유일한 눈이 된다.
2. **하루 총량 상한과 `daily_limit` 응답** (M): Durable Object(무료 SQLite)나 KV로 하루 호출 수를 세어 한도 앞에서 스스로 멈추고, 다음 날 자동 복구. IP 제한이 인스턴스별인 약점(H1)을 막는다. KV는 무료 쓰기 하루 1000번 제한이 있어 DO가 낫다. 무료 요금제에서 되는지 확인 필요.
3. **시연 코드(선택)** (S~M): `ACCESS_CODE` 비밀 변수와 앱 설정 칸에 코드를 넣는 방식. 교수님·팀원에게만 코드를 주고 공개 주소는 코드 없이는 403. 한도 소진이나 남용이 한 번이라도 보이면 켜는 비상 카드. 배포 후 코드가 번들에 들어가지 않으므로 Origin 위조보다 한 단계 강하다.
4. **"이 앱이 보내는 것" 안내 한 화면** (S): 기능별로 무엇이 어디로 가는지(사진·녹음 → Cloudflare → Google, 상품명 → 다나와·Gemini, 구글 캘린더 링크), 저장 여부, 지우는 법(기록은 기기에만 있음)을 표 하나로. README에도 같은 표. 공개 앱의 신뢰와 국외 전송 고지에 필요하다.
5. **스모크 시험 스크립트** (S): `eval/smoke.ts` 같은 한 파일로 아래 체크리스트 2-a~2-e를 자동으로 돌리고(잘못된 본문 + 실제 호출 각 1번) 결과를 한 화면으로 보여 준다. 재배포마다 쓴다.

## 6) 이 관점에서 가장 먼저 할 일 3개

1. **한도와 차단 수단부터 확정**: 구글 키 프로젝트에 결제가 없는지, 이 모델의 분당·일일 무료 한도 숫자(AI Studio), 휴대폰에서 끄는 방법(`AI_ENABLED` 변수 또는 키 삭제)이 실제로 되는지 확인하고, 시연 영상·스크린샷 백업을 만든다.
2. **코드 세 줄 보완 후 배포**: Gemini 429 구분(제안 1), 키 누락 시 503(제안 2), `observability`·`preview_urls` 명시(제안 7). 모두 작고 테스트가 쉽다.
3. **계획서 Task 17을 안전한 순서로 바꿔 수행**: 두 번째 Worker로 배포판 시험(`.env.production`은 운영 주소로만 커밋), 잘못된 본문으로 429·403·400 확인, 실제 호출은 네 경로 1번씩, 다나와는 `off` 그대로. 아래 체크리스트를 그대로 쓴다.

### C. 서버 스모크 (curl, 허용 Origin은 `-H "Origin: https://lumos0107.github.io"`)
- [ ] 주소를 브라우저 주소창에 직접 열면 `{"error":"forbidden"}`만 보인다(Origin 없음).
