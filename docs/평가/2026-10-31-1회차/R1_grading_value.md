- 평가 정답(가격표·치수·녹음)을 Claude가 쓰지 않는다. 지금 정답이 Claude 작성이라는 점이 H3의 핵심이다. 안내서는 양식만 만든다.
- README 4~6장의 학생 목소리 부분(장단점, 배운 점)은 Claude가 완성 문장으로 채우지 않는다. 사실과 숫자 정정, 빈칸 초안, 근거 링크까지만이다.
- 합성 자료 결과를 정확도처럼 쓰지 않는다(docs/ai-eval.md:172의 원칙). 스크린샷에는 "합성 사진"이라고 적는다.
- 스킬 효과를 과장하지 않는다. "스킬 없이도 결과는 대부분 맞았다"는 한계를 README 스킬 장에 그대로 남긴다. 이 정직함이 질문 1번에 대한 가장 좋은 답이다.

## 4. 다른 토론자와 부딪힐 만한 지점

- **사용자 관점(A)**: 가7·가6·나4는 내 관점에서도 올려 줄 수 있다. 다만 카드 요약형(M~L)과 개인정보 안내 축소(나9)는 이번에 넣지 않는다. 나9는 B가 강점으로 꼽은 정직한 고지를 약하게 만든다.
- **안전·운영(C)**: 가5(작은 보완)와 나8은 같이 간다. 반면 하루 총량 상한(M), 시연 코드, `/api/status`는 시연 한 번의 위험에 비해 크다. 대신 시연 날 AI Studio 사용량 확인과 백업 영상(나5)을 쓴다.
- **접근성·문구(D)**: 가8·가10은 싸니 양보할 수 있다. 가9(M)는 한 회차를 따로 줘야 한다는 점에서 이번에는 반대한다.
- **기획(E)**: E 스스로 "배포와 평가 1회가 선행 조건"이라고 썼다. 그 선행 조건을 이번 회차에서 하고, C1(규칙 대 Gemini)은 그 다음 회차의 1순위로 두자는 제안이다.

## 5. 제작자만 정할 수 있는 것

1. 마감일(PRD.md:7 '미정'). 위의 선 긋기가 여기에 달렸다.
2. PRD '제작자 확인 전' 23곳 판정(받아들임·바꿈, 이유 한 줄). 특히 R7(카메라만 열리지 않게), 60초 대기, R13(담으면 받아쓰기 끊기), 상품명을 고치면 브랜드 비우기, 다나와 켤지.
3. 문구 안 승인: 가3 "AI가 읽은 내용", 나3 온라인 가격 확인 문구, 용어 풀이(D 제안 9). PRD 고정 문장이므로 제작자 승인이 필요하다.
4. 배포: 서버 배포(Gemini 키는 배포 날 새로 만들고 결제 연결 없음 확인, workers.dev 이름), `.env.production`, main 합치기, push, 폰으로 배포판 확인. README에는 push를 제작자가 한다고 되어 있다.
5. 실측: 가격표 사진 6~10장을 직접 촬영하고, 정답을 직접 적고, 잠근 뒤 평가용으로 한 번 돌려 F43 성적표를 채우는 일(docs/ai-eval.md:13에 제작자가 마지막 판에서 한 번 돌린다고 적혀 있음).
6. "AI는 읽기만"(PRD.md:49) 원칙을 유지할지. 내 권고는 발표 전에는 유지다. 바꾸면 C3 같은 생성 기능이 열리는데, 그 평가를 이번에 못 하고 질의응답에서 위험하다.
7. 다나와 자동 조회를 공개 배포에서 켤지. 권고는 계속 꺼 둠(PRD.md:591의 약관 문제)이고, 시연이 필요하면 로컬에서만 켠다.
8. 교수가 모델을 직접 다루거나 비교하는 것을 요구했는지(PRD.md:702 조건). 요구가 있었다면 다5가 추가 기능 1순위가 되고 나머지는 줄어든다.
9. README 4~6장을 자기 말로 쓰고, 예상 질문 9개(B)에 대한 답을 연습하는 일. 특히 질문 3(숫자 반복), 4(23곳), 7(재시도 규칙).
10. 14단계의 사용자 확인 기록(TODO.md:43), 15-8의 로컬 직접 확인, 실기기 확인(아이폰 사파리 녹음 mp4, 안드로이드).

12. 개인정보 안내를 줄일지(나9)와 한도 숫자(AI Studio에서 읽기).
