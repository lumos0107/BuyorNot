# 토론 2라운드: 사용자 가치 관점 (토론자 1)

읽은 것: 내 R1, `R1_grading_value.md`(토론자 2), `R1_cost_risk.md`(토론자 3). 두 가지를 저장소에서 다시 확인했다.
- 읽은 값에 단가 숫자가 없다: `worker/src/readTag.ts:15·35`에 `priceBasis`(라벨)만 있고, `src/logic/bundleFill.ts:26`에는 "단가로 총가격을 추정하지 않는다(PRD F32)"가 있다.
- .ics: `src/logic/calendar.ts:94`는 `TRIGGER:PT0M`(일정 시각에 바로 울림)이고, `WishlistScreen.tsx:770-772`의 내려받기 버튼은 누른 뒤 화면 반응이 없다.
품 눈금: S 0.5일, M 1일(brief 기준). 이번에도 내 추정이다.

## 1. 동의하는 것

1. **새 AI 기능은 이번 회차에 만들지 않는다.** 둘 다 같은 말이고 나도 동의한다. 성적표(`evalSummary.json`)가 비어 있는데 AI 기능이 늘면 "정확도 숫자 없음"이 더 커진다. 내 추가 기능 두 개(중고 링크, 회고 안내)는 AI·서버가 없어서 이 우려에 걸리지 않는다.
2. **실제 Gemini 호출 0번, `worker/src`의 프롬프트·스키마와 `eval/` 정답 해시는 건드리지 않는다**(비용·위험 실행 규칙 2·4). 사용자에게 보이는 값이 평가 기록과 어긋나지 않게 하는 규칙이라 내 관점에서도 맞다.
3. **문서 사실 정정과 PRD 9장 대조는 확정이다**(R1의 G8 = 채점 가1·가2, 비용 K2·K3). 사용자 점수는 1이지만 S이고 코드 위험이 없다.
4. **가장 먼저 할 것: 링크 오염, 치수 읽기 문구, 담은 직후 피드백.** 세 토론자 모두 앞쪽에 둔다(채점 가3·가4, 비용 K1·K6a).
5. **정직성 경계**(채점 3장). Claude는 "제작자 확인 전"을 "제작자 확인"으로 바꾸지 않고, 평가 정답을 쓰지 않고, README의 학생 목소리 부분을 완성 문장으로 채우지 않는다. 합성 자료 결과를 정확도처럼 쓰지 않는다. 전부 동의한다.
6. **카드 요약형 접기, 알림 칸 통일은 이번 회차에서 뺀다.** 셋 다 같은 판단이다(채점 가9, 비용 K11·I10).
7. **중고·대여 링크는 싸고 안전하다**(비용 N1: 위험 5, 기획 4). 사용자 가치와 같은 방향이다.

## 2. 동의하지 않는 것

1. **담은 직후 피드백(R1 G2)은 C선이 아니라 꼭 할 것이다.** 채점 가7은 이 항목을 점수 3, C선(여유 시)에 두면서 이유 칸에는 "모든 시연이 담기로 끝나는데 화면에 아무 반응이 없다"고 적었다. 이유와 위치가 서로 어긋난다. 근거는 A-H2: 확인 문구는 폼 맨 위(문서 y≈336)에 있고 화면은 스크롤 약 790px에 머물며 새 카드는 y≈3890이다. 저장소에서도 안내는 폼 안 글 하나뿐이다(`WishlistScreen.tsx:419-425`, 스크롤·포커스 이동 없음). 비용 토론자도 1층에 둔다(K4, 위험 4). 2 대 1이다.
2. **"문구 승인을 받은 뒤 PRD → 테스트 → 코드"(채점 2장)를 그대로 따르면 제작자 대기가 병목이 된다.** 새 PRD 결정이 늘수록 '제작자 확인 전' 23곳이 더 불어나 학생 판단이 흐리다는 B-H4가 커진다. 제 제안은 이렇다. 이번에 새로 생기는 Claude 결정은 다섯 개로 묶어 시작 전에 한 번에 보여 준다(5장 2번). 답이 없으면 `updating-prd` 규칙대로 "Claude 결정 + 9장 한 줄"로 진행하고 판정표에 한 줄씩 넣는다. 승인 대기로 개발이 멈추지 않게 한다.
3. **작은 접근성·대비 묶음은 "낮음"이 아니라 should다**(채점 가8 점수 2·가10 점수 1에 반대). 입력 테두리가 흰색 대비 1.24:1이다(D-M3, `index.css:256·282·536`). 밝은 곳에서 폰으로 볼 때 입력 칸이 안 보이는 문제라 채점이 아니라 사용 문제다. S이고 CSS 위주라서 비용 토론자 K7도 다룬다. 단 항목별 커밋으로 끊는다는 비용 쪽 제안은 받는다.
4. **.ics 정리는 비용 K9의 "예비"가 아니라 should다.** 앱 밖에서 사용자를 부르는 장치가 이것뿐이다(E: 담은 뒤 다시 열 이유가 고민 끝나는 날 하루). 그런데 파일은 일정 시각에 바로 울리는 알람(`calendar.ts:94`)이고, 시각은 담은 시각 기준이라 A가 받은 파일은 새벽 1시 22분이었다. 누른 뒤 화면 반응도 없다(`WishlistScreen.tsx:770-772`). 알림 시각 선택이 코드 변경이라 품은 S~M으로 잡는다.
5. **회고 안내 줄은 could이지만 버리지 않는다**(채점 다3 점수 2에 부분 반대). `reviewDue`는 결정 기록 탭에서만 쓰인다(`HistoryScreen.tsx:189`). 목적 질문 "충동구매를 줄이나요?"에 답하는 데 필요한 순환이다. 다만 비용 쪽의 "1~2층이 초록일 때" 조건은 맞다.

## 3. 양보하는 것

1. **README '스킬로 과제를 한 방법' 장 뼈대는 꼭 할 것으로 올린다.** 내 점수는 1이었지만 채점 5·비용 5(코드 위험 0)이고 가장 큰 배점(스킬)이 발표 원고에 한 줄도 없다는 사실(README 검색 0건, B-H1)은 어떤 사용자 기능보다 먼저 보인다. 사실·표·뼈대까지만 하고 문장은 제작자가 쓴다.
2. **개인정보 안내 반복 줄이기와 "이 앱이 보내는 것" 한 화면은 이번 회차에서 뺀다.** 채점 나9와 비용 I6의 근거를 받는다. 지금의 반복은 B가 "잘된 점"으로 꼽았고(숨기지 않음), C는 고지를 늘리자는 쪽이라 정책 충돌이다. 제작자가 정한 뒤 2회차에 한다. R1의 I2는 "한 줄 설명"만 남긴다.
3. **치수 읽기 "이중 읽기"는 하지 않는다.** 이미 R1에서 뺐다. 호출이 두 배가 되고(한도), 실제 호출 0번 규칙과 맞지 않는다. 같은 사진·실제 캡처를 여러 번 읽혀 보는 일은 제작자 실측(5장 4번)으로 넘긴다.
4. **R1의 I4(단가 가격표를 앱이 산수로 복구)는 철회한다.** 비용 K10b의 지적이 맞다. 응답에 단가 숫자가 없고 `price` 하나와 `priceBasis` 라벨뿐이라 앱이 확인할 수 없고(`readTag.ts:15·35`), PRD F32가 "단가로 총가격을 추정하지 않는다"고 못 박았다(`bundleFill.ts:26`). 남기는 것은 "거절 이유를 말하고, 눌리지 않는 [채우기]를 없애고 '직접 넣어 주세요'로 안내"하는 화면 수정(비용 K10a)뿐이다. 이쪽이 사용자 가치의 대부분이다.
5. **가격 비교 칸 예시값을 비우는 안(R1 G4의 앞부분)은 철회하고 문구를 사실로 고친다.** 비용 I5가 맞다. `startWithExample`이 `App.tsx:83`과 `CompareScreen.tsx:106·325` 등 여러 곳과 테스트에 걸려 있고 시연 예시 정책은 제작자 결정이다. 대신 `CompareScreen.tsx:611`의 문장("'예시 넣기'를 누르면 채워져요")이 이미 채워진 화면과 어긋나는 것만 고친다("예시 값이 들어 있어요. 내 값으로 바꾸거나 ‘초기화’를 눌러 주세요" 같은 것).
6. **서버 보완(429 구분, 키 누락 503)은 "배포가 이번 회차에 확정될 때만"으로 내린다.** R1에서는 S로 보았지만 비용 K5의 파급 목록이 맞다. 핸들러 4곳, AC60(PRD.md:755), `worker/test/gemini.test.ts:149`, `eval/score.ts:118`에 번진다. 사용자가 효과를 보는 것도 배포 뒤다. 채점 가5는 A선인데 "배포를 이번에 하는 경우에만 필요"라고 스스로 적었다.
7. **홈에서 가격표 담기 버튼, 기록 지키기(`storage.persist`·홈 화면 앱), 친구에게 물어보기는 이번에 하지 않는다.** 기록 지키기는 근거가 "iOS 사파리 7일 삭제"인데 E 스스로 "확인 필요"이고 내가 확인하지 못했다. 근거 확인이 먼저다.
8. **카드 높이는 이번에 줄이지 못한다.** 사용자 가치로는 가장 큰 개선이지만 세 토론자 모두 뺀다. 카드 높이를 다시 재는 일(E의 S 제안)은 2회차 기획을 위해 해 둘 만하다.

11. **교수가 모델 비교·직접 학습을 요구했는지**(PRD.md:702 조건). 요구가 있었다면 이유 분류기 비교가 추가 기능 1순위가 된다.
12. **시연·운영**: 시연 백업 녹화, 채점 뒤 AI를 끌지(`AI_ENABLED=false` 또는 키 삭제), 지인 시험 사용 여부, 쇼핑앱 공유 글 30~40개 모으기(2회차 붙여넣기 담기 준비).
