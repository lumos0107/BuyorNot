## 6) 잘된 점

1. **평가 → 결정 → 개발 → 재평가의 고리가 문서로 닫혀 있다.** 평가 기준을 미리 고정했고(평가기준.md), 결정 범위(R29)를 넘는 것은 만들지 않았다. 새 AI 기능은 "정확도 숫자가 생긴 뒤로" 미루고 지켰다(DEVLOG.md:1028). 보류한 후보에는 이유를 적었다(1회차.md:47~56). 평가에 맞춰 점수만 올리는 일을 스스로 막았다.
2. **스킬 위반을 숨기지 않고 고쳤다.** README가 "평가가 찾은 스킬 규칙 위반(P5)"을 직접 밝히고(README.md:158), 검사를 더해 재발을 막았다. 교수가 "스킬이 실제로 지켜졌나"를 물을 때 가장 좋은 답이 된다.
3. **AI 출처를 화면에 밝혔다.** "적힌 내용"을 "AI가 읽은 내용 · 사진과 같은지 확인해 주세요"로 바꾸고 원본을 크게 보게 했다. 그러면서 이것이 정확도 해결이 아니라고 적었다(1회차.md:91).
4. **P1 조사가 과학적이다.** 같은 바이트를 재현하고(브라우저 두 종류로 바이트 일치 확인), 서버 판 해시를 대조하고, 흰 그림 대조군을 두고, 예측을 먼저 적은 뒤 불렀다. 결론은 증거만큼만 냈다.
5. **사실 대조 습관.** 리뷰어가 README 숫자·인용 줄·링크를 원본과 글자 단위로 대조했고, 총괄 자신의 브리프 오류(GPT 기록 파일 이름)까지 잡아 고쳤다(DEVLOG.md:1105~1106).
