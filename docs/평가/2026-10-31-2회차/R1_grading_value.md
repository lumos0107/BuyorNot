## 0. 먼저: P1 정정이 평가자 다섯 명의 글을 어디까지 바꾸나

## 2. P1 정정은 B4(정직성)의 강점인가, 어떻게 보여 주나

**의견: 조건부로 강점이다. 조건은 네 가지.**

강점이 되는 근거(모두 파일에 있다).
1. 이상 징후를 알아챈 방식. 새로 찍은 사진인데도 1회차와 '글자·숫자·kind까지 똑같다'는 점(A 사용자 A5)이 단서가 되었다.
2. 독립된 근거 셋(서버 로그에 요청 없음, 모의 응답과 일치, 직접 보내면 정답)으로 닫았다(1회차.md:91).
3. 지난 기록을 지우지 않고 정정을 덧붙였다(DEVLOG.md:1132). `evaluating-ai`가 '이전 성적과 노출 이력을 지우지 않고 남긴다'고 하는 방식과 같다.
4. 자기 잘못을 이름 붙여 적었다. "서버 로그를 보지 않은 탓"(F_P1 머리, DEVLOG.md:1131).
5. 평가 조건을 고쳤다(평가기준.md:15·16, 72의 새 브라우저, POST 줄로 세기, 두 평가 결과를 비교에서 뺌).
6. 틀린 증거로 프롬프트·서버를 바꾸지 않았다(0장 2번).

약점(말하지 않으면 질의응답에서 드러난다).
- 1회차 조사는 실제 호출 3번을 쓰고 '모델이 지어냈다'로 틀리게 결론 냈다. 평가 두 번이 오염됐다.
- B 교수 평가가 '조사가 엄밀하다'로 가점(+1)을 준 근거는 이제 '조사가 결국 틀렸다'를 포함한다. 가점의 근거가 정정 과정 쪽으로 옮겨 간 것이지 사라진 것은 아니다. 75점 추정은 크게 안 바뀐다고 본다.
- 정정이 여섯 파일에 흩어져 있고 README·ai-eval.md에서는 찾을 수 없다(grep 확인). 채점자는 PRD.md:726의 긴 괄호부터 만난다.
- '이 캡처의 실제 기록은 3번 모두 정답'(1회차.md:91)은 합성 캡처 한 장, 직접 호출 3번이다. 정확도로 읽히면 안 된다.
