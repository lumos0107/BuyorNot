### A4 묶음 비교 카드 A를 사진으로 채우기 (3점, 스텁으로 확인)
- 실제 호출이 남지 않아 1회차에 기록된 응답 값(`price 6480, priceBasis "100mL", size 355, unit "mL", count 6`, 이름·sizeText는 내가 채움)을 그대로 돌려주게 하고 `img_bundle.png`를 올렸다. 화면: 사진 미리보기 아래 상자에 "AI가 이 가격을 100mL당 가격으로 읽었어요. 묶음 전체 가격이 아니라서 채우지 않았어요. 사려는 묶음의 전체 가격과 용량·개수를 직접 입력해 주세요."와 [취소]만(26_bundle_unitprice_replay.png). 이유가 분명하고 눌리지 않는 [채우기]가 없어졌다. 포커스도 이 안내로 간다.
- 같은 값에서 `priceBasis`만 비운 성공 경우(이것도 스텁): "읽은 내용: 코카콜라 제로 슈거 · 355mL × 6캔 / 채울 값: 가격 6,480원 · 355mL × 6개 / [채우기] [취소]" → [채우기] 누르면 6480 / mL / 355 / 6이 들어가고 포커스가 가격 칸으로 간다(27, 28_bundle_filled.png). 1회차에서 못 본 경로이고 매끄럽다.
- 감점 이유: (1) 이번 회차에 모델이 이 라벨을 어떻게 읽는지는 다시 보지 못했다. 프롬프트가 바뀌지 않았으므로 마트 가격표처럼 단가가 같이 찍힌 라벨은 여전히 거절될 것으로 본다. (2) 거절 문장이 AI가 무슨 숫자를 단가로 읽었는지(6,480원) 말하지 않아, 사진에 큰 글씨로 6,480원이 보이는 사용자는 "이게 전체 가격인데?" 하고 직접 다시 친다. - '3단 오픈 책장' 카드 → 놓을 자리 확인: 놓을 곳 "침대 옆 벽 70×35×130", 물건 60×30×120 → [확인하고 저장]. 결과 "입력 치수상 침대 옆 벽에 들어가요. / 방향 1: 가로 10cm 남음 · 깊이 5cm 남음 · 높이 10cm 남음 → 들어가요 / 방향 2: 가로 40cm 남음 · 깊이 25cm 넘침 · 높이 10cm 남음 → 안 들어가요 / 방향 2는 물건을 바닥에서 90도 돌려 놓은 경우예요. / 입력한 치수만 비교했어요. …"(17_fit_result.png). 여기까지는 좋다. 이번엔 빈 상태에서 시작해 놓을 곳이 예시 값으로 채워지는 일(1회차 M5)은 없었다.
- **치수 읽기(실제 호출, 04:28:59 올림 → 04:29:06 결과)**: 같은 `src_capture.html` 캡처. 사진의 표는 "제품 크기 가로 60 × 세로 30 × 높이 120cm", "포장 크기 가로 124 × 세로 32 × 높이 12cm"(img_capture.png). 서버가 돌려준 것(요청 89 응답 본문 그대로):
  - `"접었을 때: 가로 58 x 깊이 6 x 높이 96cm"`, label 접었을 때, kind product, w58 d6 h96
  - `"펼쳤을 때: 가로 58 x 깊이 62 x 높이 96cm"`, label 펼쳤을 때, kind product, w58 d62 h96
  - `"가로 60 x 깊이 8 x 높이 98cm"`, label 없음, kind package, w60 d8 h98
  - 사진과 맞는 숫자는 세 번째 줄의 가로 60 하나뿐이다. 나머지 58·6·62·96·8·98은 사진에 없고, '접었을 때'·'펼쳤을 때'·'깊이'라는 말도 없다(사진은 '세로'). 세 번째 줄은 포장(package)이라 했지만 진짜 포장 치수 124×32×12와도 다르다. 진짜 값 60×30×120과 124×32×12는 어느 줄에도 나오지 않았다.
  - **1회차 A가 본 세 줄과 글자·숫자·kind까지 똑같다.** 이번 입력은 내가 새로 찍은 그림이라 1회차 그림과 바이트가 다르다. 앱이 실제로 보낸 그림을 요청 본문에서 꺼내 보니 390×640 JPEG 29,828바이트(sha256 앞 16자 `f75ca5a2ab9cccd2`)이고 표 글자가 또렷하다(`sent_capture.jpg`). 즉 앱이 흐린 그림을 보낸 탓은 아니다. 1회차 조사(F_P1)에서 같은 캡처를 직접 2번 불렀을 때는 2번 모두 맞았으므로, 이 캡처의 기록은 앱 경로 2번 모두 같은 답으로 틀림, 직접 호출 2번 맞음이다. 출력의 '접었을 때·펼쳤을 때'와 `x` 구분자는 `worker/src/readSize.ts:12-13` 프롬프트의 예시와 같다.
- **화면 문구**: 후보가 여러 개라 라디오로 나오고 이름은 "접었을 때 · AI가 읽은 내용: ‘접었을 때: 가로 58 x 깊이 6 x 높이 96cm’" 식이다(19_size_read_result.png). "사진과 같은지 확인해 주세요"는 라디오에는 없고, 하나를 고르면 아래 확인 줄이 "접었을 때 · AI가 읽은 내용: ‘…’ · 사진과 같은지 확인해 주세요 / 제품 치수예요. / 넣을 값: 가로 58 · 깊이 6 · 높이 96cm / [넣기] [취소]"가 된다(23_size_choice_confirm.png). 브리프에 적힌 "AI가 읽은 내용 · 사진과 같은지 확인해 주세요"가 이렇게 둘로 나뉘어 들어가 있다. 확인 요청은 다른 글과 같은 회색 보통 글씨이고 [넣기]는 바로 눌린다.
- **캡처 크게 보기**: 작은 미리보기 바로 아래 접이식. 펼치면 279×457(원래 비율)로 후보 상자 바로 위에 붙어, 한 화면에서 표의 "가로 60 × 세로 30 × 높이 120cm"와 AI의 "58 x 6 x 96"을 함께 볼 수 있다(21_capture_large_top.png). 대조에는 확실히 도움이 됐고, 나는 이것을 보고 틀렸다는 것을 알아 [취소]를 눌렀다. 취소하면 내가 친 60/30/120이 그대로 있고 포커스는 캡처 고르기로 돌아간다(24_size_cancel.png). 다만 펼쳐야 보이고, 폰 폭에서 표 글자는 약 10px이다. 접힌 작은 미리보기는 279×240으로 세로가 눌려 찌그러져 보인다(20_size_read_top.png, `src/index.css:633-639`에 높이 상한만 있고 비율 유지 설정이 없음).
- 점수 이유: 확인을 돕는 화면은 1회차보다 낫지만 세 후보 중 사진의 치수와 맞는 줄이 하나도 없었다. 놓을 곳이 조금 좁았다면(예: 깊이 20cm) 지어낸 깊이 6cm로 "들어가요"가 나온다.

### A6 캘린더, 결정·회고, 사기 전에 한 번 더 (4점)
- 캘린더: [캘린더 파일(.ics)]을 누르면 `buyornot-2026-11-03.ics`가 내려오고 앱 안에는 아무 안내가 없다(29_after_ics.png). 파일의 시작 `DTSTART:20261102T192524Z`(11/3 04:25 KST), 알람 `TRIGGER:PT0M`, 설명에 처음 적은 이유와 앱 주소. 구글 캘린더 링크도 `dates=20261102T192801Z/…`(에어팟, 04:28 KST)로 담은 시각 + 3일이다. 새벽 알람(I4)은 그대로다.
- 사기 전에 한 번 더: [구매함] → "사기 전에 한 번 더 · 걸리는 점 1개 / 갖고 싶은 정도: 담을 때 4 / 고민 기간이 2일 23시간 남았어요 / 한 번 생각해 볼 질문: 없으면 어떤 문제가 있나요? · 한 달 뒤에도 쓸까요? · 지금 쓰는 게 있나요? / 그 밖에 3개 보기 / 이유와 답을 돌아보고, 살지 정해 보세요." + 결정 메모 + [구매함 확인] [취소](30_buy_check.png). 훈계 없이 묻기만 해서 좋다.
- 결정: [구매함 확인] → 맨 위로 가서 "‘나이키 에어포스 1’를 구매함으로 옮겼어요. [되돌리기]"(31_after_buy.png). [구매 포기]도 같은 식(37_after_skip.png).
- 회고: 결정 기록에는 바로 회고 칸이 없다. 코드상 구매 7일 뒤에 열린다(`src/logic/summary.ts:9` `RETRO_AFTER_MS`). 결정 날짜를 8일 전으로 바꿔 다시 열자 "잘 샀나요? 잘 샀어요 · 그저 그래요 · 후회해요 / 한 줄 회고 (선택) / [회고 저장]"이 나오고, 저장하면 "회고: 그저 그래요 · …"와 요약 "회고 1건 중 후회 0건", 포커스는 [회고 고치기](34, 35_review_saved.png).
- 감점 이유: 구매함으로 옮긴 카드에 "7일 뒤에 잘 샀는지 물어볼게요" 같은 말이 없고, 회고할 때가 되어도 고민 중인 물건 탭 첫 화면에는 아무 표시가 없다(33_home_review_due.png). 사용자는 결정 기록 탭을 스스로 열어야 회고를 만난다(N3 보류 그대로).

## 3) 잘된 점
- **담은 뒤가 분명해졌다.** 새 카드로 이동, 제목 포커스, "방금 담았어요."가 세 번 모두 같았다. 1회차에서 가장 답답했던 부분이 풀렸다.
- **사진 초안 링크 처리가 정직하다.** 이름을 바꾸는 순간 링크를 지우고 왜 지웠는지, 새 링크가 어디 있는지 알려 준다. 저장 값도 맞다(`url: null`).
- **결과 화면 문구가 사실대로다.** 온라인 가격 확인 맨 위 줄, 묶음 단가 거절 이유, 가격 비교 예시 안내("처음에는 예시 값이 들어 있어요. … ‘초기화’를 누르면 입력칸을 비우고, ‘예시 넣기’를 누르면 예시 값을 다시 넣어요.", 05_price_tab.png, 25_bundle_tab.png)가 모두 실제 동작과 맞는다.
- **AI 결과를 그대로 넣지 않는 구조.** 가격표·묶음·치수 모두 값을 보여 주고 사용자가 [채우기]·[넣기]를 눌러야 들어가며, 취소하면 내가 친 값이 남는다. 치수 읽기에 '캡처 크게 보기'가 생겨 대조가 실제로 가능해졌다.
- 화면 크기 안정: 네 탭 모두 가로 넘침 없음(scrollWidth = clientWidth = 345). 이번 세션 콘솔 오류·경고 0건.

## 4) 문제

### 높음
**H1. 치수 읽기가 사진에 없는 치수를 다시 내놓음(P1 재발).**
- 재현: 고민 중 카드 → 놓을 자리 확인 → 상품 페이지 캡처에서 치수 읽기 → `src_capture.html`을 390×640으로 찍은 그림. 결과는 위 A5의 세 줄로 1회차와 똑같다(19_size_read_result.png, 요청 본문 `req89_read_size_body.txt`, 보낸 그림 `sent_capture.jpg`).
- 앱이 보낸 그림은 또렷하므로 원인은 모델 쪽 출력이다. 같은 틀린 답이 두 번 글자까지 똑같이 나왔으니 우연한 흔들림보다는 특정 입력에서 되풀이되는 실패로 보인다. 다만 표본은 이 캡처 하나에 앱 경로 2번뿐이다.
- 사용자 쪽 위험: 고른 뒤 확인 줄의 "사진과 같은지 확인해 주세요"는 눈에 띄지 않고, 큰 캡처는 접혀 있으며, [넣기]는 한 번에 눌린다.

### 중간
**M1. 첫 화면에서 '며칠 두고 다시 정한다'가 안 보임(I3 보류 그대로).** 목적 문장은 빈 목록 상자(y≈1190)와 접힌 "며칠 고민하면 뭐가 좋을까요?"에 있다(02_home_full.png).

**M2. 회고 차례를 알려 주지 않음(N3).** 구매 7일 뒤에야 결정 기록 탭 카드에 회고 칸이 생기고, 그 사실을 미리 말하거나 홈에서 알려 주는 곳이 없다(31, 33).

**M3. 묶음 단가 라벨 거절 자체는 그대로이고, 사진으로 채운 뒤에도 다른 칸에 예시가 남음.** 거절 문장은 좋아졌지만 6,480원처럼 사진에 크게 찍힌 총액을 사용자가 다시 쳐야 한다. 카드 A만 사진으로 채우면 B와 사용량은 예시 세제 값이라 결과 문장이 의미 없는 비교가 된다(28_bundle_filled.png). 이번 회차엔 스텁으로만 봤다.

### 낮음
- **L1.** 캘린더 알람이 담은 시각 + N일이라 이번엔 11/3 04:25. .ics를 눌러도 앱 안 안내 없음(I4, 1회차 L3 그대로).
- **L2.** 폼 맨 위 "‘…’를 담았어요. 3일 뒤에…"가 다른 물건을 구매함·구매 포기로 옮긴 뒤에도 남음(1회차 L7 그대로, 31_after_buy.png).
- **L3.** 가격표 읽기 결과 칸 이름 "가격 조건/포장 표기/개수", 온라인 확인 결과 아래 같은 문장과 비슷한 버튼 두 개(1회차 L1·M3 일부 그대로).
- **L4.** 같은 가격표를 두 번 읽히면 상품명이 달라짐(모델 번호·'자급제' 포함 여부). 이름이 검색어와 담기 이름으로 가므로 사용자가 보기엔 '그때그때 다른 앱'이다.
- **L5.** 치수 읽기의 작은 미리보기가 세로로 눌려 보임(279×240, `src/index.css:633-639`).
- **L6.** 같은 뜻의 말이 기능마다 다름: 묶음 "읽은 내용" / 치수 "AI가 읽은 내용".
- **L7.** 위쪽 탭 줄과 가격 비교 하위 탭 줄 오른쪽에 스크롤바 화살표가 '구독'·'가격표 사진' 글자를 가림(`tablist` scrollHeight 44 > clientHeight 43, 01_first.png, 05_price_tab.png, 1회차 L4 그대로).
- **L8.** 카드 한 장 1,342px. 물건 3개면 고민 탭이 4,200px를 넘는다.

## 부록: 한계와 하지 못한 것
- **내 실수로 실제 호출 1번을 낭비함.** 가격표 사진을 올릴 때 내 스크립트가 파일 선택 창을 받아 파일을 넣었는데, MCP도 같은 창을 잡고 있어 결과가 돌아오지 않은 줄 알고 MCP 도구로 한 번 더 올렸다. 같은 사진이 2번 모델에 갔다(요청 85·86). 그래서 A4는 실제 호출 없이 1회차 기록 값으로 스텁 확인만 했다. 덕분에 같은 사진·temperature 0에서 상품명이 달라지는 것(L4)은 봤다.
- 회고는 결정 날짜를 localStorage에서 8일 전으로 바꿔 확인했다(앱 화면 동작은 그대로, 시간만 앞당김).
- 말로 담기는 마이크가 없고, 모르고 녹음이 보내지면 호출 수를 넘을 수 있어 누르지 않았다. 다나와 조회 켠 상태, 구글 캘린더 실제 열기, 실제 휴대폰의 터치·스크롤바는 보지 못했다. AI 성적표는 화면 어디에도 나오지 않았다(1회차와 같음).
- 1회차는 예시 물건이 있는 상태에서 시작했고 이번엔 빈 상태라 A1·M5 비교는 조건이 조금 다르다.
- 모든 AI 결과는 한 번씩 본 표본이라 정확도 수치가 아니다.
