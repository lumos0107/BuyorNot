# 절약·저축 2단계 구현 계획

**목표:** PRD v0.49 F54~F60·F20 보강(AC117~AC132). 집에 있는 것(C)과 자잘한 지출(D)을 사용자 기록만으로 만든다. `saving` 브랜치에서 커밋만 하고 push하지 않는다.

**순서:** 저장·백업 → 집에 있는 것의 남은 정도 → 유통기한·버림 → 산 값 → 해 먹는 것 → 있어서 안 삼 → 자잘한 지출 → 배달 비교. 작업마다 먼저 실패하는 AC 테스트를 만들고, 구현 뒤 전체 테스트·lint·tsc·check_all을 통과시킨다. 문구는 PRD 따옴표 그대로. 기존 저장 형식은 더하기만 한다.

**저장:** `buyornot.pantry.v1`과 `buyornot.spending.v1`을 새로 둔다. 각 훅은 원문 비교로 다른 탭의 먼저 쓴 값을 덮지 않고, 손상값은 초기화 전까지 덮지 않는다. `backupVersion: 3`에는 두 부분을 필수로 넣고, v1·v2에는 없는 부분을 현재 기록으로 유지한다. 불러오기 파일은 모든 부분을 검증한 뒤에만 반영한다. 옮긴 돈은 은행에서 실제 옮긴 기록으로만 계산한다.

**번호:** PRD의 실제 가장 큰 번호 F53 다음 F54를 쓴다. 설계 문서의 'F55부터'는 옛 F54 배치가 있던 때의 메모다. 제작자 판정표 #47~#54는 비워 둔다.

### Task 1: 저장 모양·훅과 백업 v3 (F54·F59·F20, AC118·AC128·AC131·AC132)

- `src/logic/pantry.ts`: 항목·산 값·레시피·사건 타입, 상한, `isPantryStore`·`parsePantry`와 새 기록을 더하고 지우는 순수 함수. `src/logic/spending.ts`: 자주 쓰는 버튼·쓴/참은 기록, 복원 검사. Node API 없이 저장값을 검사한다.
- `src/store/usePantry.ts`, `src/store/useSpending.ts`: `useBills`의 저장 결과(`ok`·`full`·`replaced`), 손상·저장 실패·storage 이벤트·백업 교체 규칙을 각 키에 적용한다. 기존 훅은 바꾸지 않는다.
- `src/logic/backup.ts`, `src/screens/BackupSection.tsx`, `src/App.tsx`: 판 3을 만들고 v1·v2도 읽는다. `pantry`·`spending`이 없는 옛 파일은 null로 돌려 지금 기록을 유지한다. 새 판에서 둘 중 하나라도 잘못되면 불러오기를 거절한다.
- 테스트 먼저: 저장 손상·상한·다른 탭·v1/v2/v3 왕복·한 부분 손상으로 전체 거절. 기존 백업 기대값은 새 필드 때문인 곳만 고치고 커밋 본문에 적는다.
- 커밋: `feat: store pantry and small spending with backup v3 (F20, F54, F59)`.

### Task 2: 집에 있는 것과 살 때가 된 것 (F54, AC117·AC118)

- 물건 탭에 `PantrySection`을 둔다. 이름·종류·남은 정도를 적고, 넉넉 → 조금 → 떨어짐을 한 번 눌러 바꾼다. 조금·떨어짐은 위쪽, 나머지는 접힌 기록에 보인다. 같은 이름과 200개 상한을 검사한다.
- 고정비의 쓰는 중인 정기배송과 이름이 같으면 ‘정기배송으로 와요.’를 보인다. 항목 추가·상태 바꿈·지우기에서 한 번 누름은 pantry 키 하나만 쓴다.
- 테스트 먼저: 빈 화면, 추가·상태·정렬, 이름 중복, 복원 손상, 다른 탭 충돌, 고정비와 이름 연결, 360px.
- 커밋: `feat: track what is at home and what is running low (F54)`.

### Task 3: 유통기한과 버린 기록 (F55, AC119·AC120)

- 식재료에만 유통기한을 받는다. 3일 안·지난 항목을 ‘먼저 쓸 것’에 날짜순으로 보인다. ‘버렸어요’ 확인 뒤 pantry 사건을 남기고 항목을 목록에서 뺀다.
- 이번 달 버린 개수·마지막 산 값 합계를 접어 둔다. 금액을 모르면 0원이며 모으기의 옮긴 돈에 넣지 않는다.
- 테스트 먼저: D-3/D-4 경계, 지난 날짜, 생필품 유통기한 손상, 버리기·취소·저장 충돌.
- 커밋: `feat: show expiring ingredients and discarded records (F55)`.

### Task 4: 산 값과 단가 비교 (F56, AC121·AC122)

- 물건에 산 날·곳·금액·용량·단위를 최대 5개 적는다. 같은 단위 종류끼리 F05 단가 규칙으로 100g·100mL·1개당을 표시한다. 다른 종류면 비교하지 않는다.
- 마지막 산 값은 살 때가 된 줄에도 보인다. 묶음 비교로 보내기는 비교 화면의 초안 흐름을 사용한다. 외부 가격 수집 없음.
- 테스트 먼저: g/kg 환산, 다른 단위 거절, 5개 상한, 날짜·금액·용량 오류, 마지막 산 값, 초안 이동.
- 커밋: `feat: compare manually recorded pantry prices (F56)`.

### Task 5: 자주 해 먹는 것 (F57, AC123·AC124)

- 레시피 이름·재료·선택 대체 금액을 적는다. 집에 있는 재료 개수 많은 순으로, 부족한 재료 이름을 보인다. ‘해 먹었어요’는 pantry 사건 한 건을 남긴다.
- 모으기에 이 사건의 대체 금액을 실제 옮긴 돈과 구분한 별도 줄로 보여 준다.
- 테스트 먼저: 재료 정규화·정렬·상한, 금액 없는 사건, 저장 충돌, 모으기 분리.
- 커밋: `feat: track meals made with ingredients at home (F57)`.

### Task 6: 있어서 안 산 기록 (F58, AC125·AC126)

- 마지막 산 값이 있는 물건에서만 ‘있어서 안 샀어요’를 쓸 수 있다. 같은 날 같은 물건은 확인 뒤 두 번째 사건을 남긴다. 물건 상태는 유지한다.
- 모으기에는 다른 대체 금액과 함께 보되 옮긴 돈·저축 목표와 합치지 않는다.
- 테스트 먼저: 값 없는 버튼, 사건 금액, 같은 날 확인·취소, 여러 탭 반영 실패.
- 커밋: `feat: record purchases skipped because an item is at home (F58)`.

### Task 7: 자잘한 지출 (F59, AC127·AC128)

- 모으기 탭에 자주 쓰는 편의점·카페·배달 버튼을 만든다. ‘썼어요’·‘참았어요’를 한 번 누르면 spending 키에 기록한다. 이번 달과 지난달 같은 날까지 종류별 횟수·금액을 따로 계산한다.
- 선택 횟수는 참고값만 보인다. 참은 기록은 모으기의 별도 줄에 놓고 저축 목표에 더하지 않는다.
- 테스트 먼저: 반복 기록, 월 경계, 버튼·기록 삭제, 상한, 손상·여러 탭, 세 숫자 분리.
- 커밋: `feat: track small recurring spending and skipped purchases (F59)`.

### Task 8: 배달 앱 총액·주문 기준 (F60, AC129·AC130)

- 가격 비교 하위 ‘배달’ 탭에 A/B 앱 이름·메뉴·배달비·정액 쿠폰·포장을 적는다. 실제 결제액과 차이를 보인다. 배달 멤버십은 맥락 줄만 보이고 자동 할인은 없다.
- 최소 주문액 미달은 주문 불가라고 표시하고, 무료배달 기준 비교는 별도다. F13 계산을 재사용하되 필요한 추가 구매를 권하지 않는다. 제작자가 이에 답하면 PRD·계획부터 바꾼다.
- 테스트 먼저: 쿠폰 상한·포장·총액·같음, 최소 주문액 경계, 무료배달 기준, 360px 하위 탭.
- 커밋: `feat: compare delivery app totals and order thresholds (F60)`.
