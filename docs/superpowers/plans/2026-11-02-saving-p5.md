# 사용 흐름 개선: 오늘 확인할 것과 빠른 담기

**목표:** PRD v0.68 F72~F73·F01·F24·F30 보강(AC163~AC171). `saving` 브랜치에서 커밋만 한다. 입력 부담 설계에는 `.claude/skills/simplifying-entry-flows/SKILL.md`를 적용한다.

**필드 점검:** 상품명·가격은 지금 기록을 만드는 데 필요한 값이다. 이유는 사기 전 점검·회고에서 쓰이지만 담은 뒤 적을 수 있다. 고민 기간은 3일을 화면에 먼저 보여 주고 상세 입력에서 바꿀 수 있다. 정도·체크리스트·링크는 선택이다. 이유를 생략하면 빈 문자열로 저장하고, 이유를 표시하는 카드·결정 기록·캘린더에서 ‘아직 적지 않음’을 명확히 다룬다. 옛 기록·백업 판 1~3과 schemaVersion 1을 유지한다.

**날짜 점검:** 고민 기간이 끝난 물건은 결정하기 전까지 남는다. 결제일·반품 기한·포인트 만료는 오늘부터 7일 뒤까지(양 끝 포함)만 세고 지난 날짜·해지·반품 완료는 제외한다. 첫 대상은 날짜가 빠른 순, 같은 날은 이름순이다. 오늘 갖고 싶은 정도 안내(F30)는 기존 집계와 포커스를 유지한다. 이 화면은 저장하지 않으며 푸시 알림이 아니다.

### Task 1: 오늘 확인할 기록 집계 (F72, AC163~AC165)

- 물건·고정비·반품 기한·포인트 만료를 기존 저장값에서만 읽는 순수 로직을 둔다. 날짜 경계·제외·정렬과 빈 상태를 테스트 먼저 확인한다.
- 기존 F30의 오늘 정도 집계는 재사용한다. 한 기록이 서로 다른 행동에 해당할 수 있음을 화면 문장으로 구분한다.
- 커밋: `feat: collect due actions from existing records (F72)`.

### Task 2: 첫 화면 요약과 대상 이동 (F72, AC163·AC166)

- 물건 화면 제목 아래 짧은 오늘 요약을 두고 F30 안내를 그 안으로 옮긴다. 각 보기 버튼은 해당 탭으로 이동한 뒤 첫 대상의 카드와 접힌 부모를 열어 포커스를 준다.
- 테스트 먼저: 기존 오늘의 고민 시험 유지, 각 탭 이동·포커스, 360px 가로 넘침·키보드.
- 커밋: `feat: show today's actions on the first screen (F72)`.

### Task 3: 빠른 담기의 빈 이유 호환 (F73, AC167·AC168·AC171)

- 빈 이유는 실제 이유가 아니라 미작성 상태다. 새 물건 저장·복원·백업, 수정·결정·회고·캘린더의 빈 이유 경로를 검사한다. 기존 이유가 있는 기록의 필수 검증은 보존한다.
- 테스트 먼저: 이름·가격과 3일 기본값, 옛 파일과 왕복, 수정해 이유 채우기, 빈 이유를 화면·캘린더에 사실처럼 표시하지 않기.
- 커밋: `feat: support wishes with reasons added later (F73)`.

### Task 4: 두 칸 담기와 상세 입력 (F73, AC169~AC171)

- 기존 접힌 담기 폼을 열면 상품명·가격·기본 3일과 담기 버튼만 먼저 보인다. ‘더 적기’에서 기존 이유·정도·기간·체크리스트·링크를 모두 사용할 수 있다.
- 테스트 먼저: 두 칸 저장, 상세 입력, 가격 비교·사진·말로 담기 초안의 펼침과 포커스, 다른 탭 선행 저장 시 작성 중 값 유지.
- 커밋: `feat: add a two-field quick wish flow (F73)`.
