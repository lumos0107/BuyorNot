# 절약·저축 3단계 구현 계획

**목표:** PRD v0.56 F61~F67·F20 보강(AC133~AC148). 사기 전(B)과 산 뒤(E)의 선택 정보를 기존 물건 기록에 더한다. `saving` 브랜치에서 커밋만 한다.

**공통 저장:** `buyornot.wishlist.v1`과 `schemaVersion: 1`, 백업 판 3을 유지한다. 새 필드는 모두 선택이다. 없는 옛 기록·v1·v2·v3 백업이 그대로 읽혀야 한다. 새 필드 하나가 손상이면 물건 기록을 손상으로 보고 덮어쓰지 않는다. 물건 수정·결정·되돌리기가 선택 필드를 뜻없이 지우지 않게 한다. 성공 안내는 화면 반영이 확인됐을 때만 띄운다. 옮긴 돈은 실제로 은행에서 옮긴 기록으로만 계산한다.

**화면:** 물건 탭의 접힌 ‘사기 전에’는 고민 중인 물건을 이름별로 보이고, 결정 기록에는 구매함 물건의 ‘산 뒤에’ 카드를 둔다. 새 화면은 기존 담기·회고 흐름을 가리지 않는다. 같은 이름의 집에 있는 것은 pantry 키를 읽기만 한다. 중고 홈페이지는 주소를 다시 확인하고 상품명·가격을 URL에 붙이지 않는다.

### Task 1: 선택 필드 저장과 백업 호환 (F61~F67·F20, AC134·AC148)

- `WishItem`에 `installment`, `usesPerYear`, `bulkUse`, `targetPriceKrw`, `priceNotes`, `returnBy`, `returnedOn`, `resale`를 선택 필드로 더한다. `storage.ts`의 복원 검사와 `reconsiderItem`의 구매 후 필드 정리를 구현한다.
- `useWishlist`에 고민 중 선택 정보를 갱신하고 구매함의 산 뒤 선택 정보를 갱신하는 한 키 저장 메서드를 둔다. 다른 탭의 먼저 저장한 기록을 덮지 않는다.
- 테스트 먼저: 각 범위·의존 필드·상한·옛 기록·백업 v1/v2/v3 왕복·손상 파일 전체 거절. 기존 테스트는 명세가 바꾼 곳만 고친다.
- 커밋: `feat: add optional before and after purchase fields (F61-F67, F20)`.

### Task 2: 할부 총액 (F61, AC133·AC134)

- ‘사기 전에’ 카드에서 개월 2~36과 월 납입금을 함께 적는다. 카드사가 안내한 금액만 곱하고 이자율은 계산하지 않는다. 일시불보다 큰 차이와 같거나 낮은 경우의 문장을 구분한다.
- 테스트 먼저: 12×30,000, 일시불과 같음, 한 칸만 입력, 저장·수정·다른 탭, 옛 기록.
- 커밋: `feat: show installment totals before buying (F61)`.

### Task 3: 사용 빈도와 빌리기·중고 (F62, AC135·AC136)

- 연 사용 횟수 1~365를 적고 1~2번이면 가격 ÷ 횟수 반올림과 대안을 보인다. 홈페이지 링크는 새 창·noopener noreferrer이고 상품명은 보내지 않는다.
- 구현 직전 당근·번개장터 홈페이지를 확인한다. 열리지 않는 링크는 빼고 PRD부터 고친다.
- 테스트 먼저: 횟수 0/1/2/3/366, 1회당 금액, 링크 URL의 query·hash 없음.
- 커밋: `feat: show cost per use and borrowing alternatives (F62)`.

### Task 4: 집에 있는 것과 중복 구매 (F63, AC137·AC138)

- 담기 폼과 ‘사기 전에’ 카드에 pantry의 이름·상태를 읽기 전용으로 연결한다. 앞뒤 공백·대소문자만 정리한 정확 일치이고, 부분 일치는 제외한다.
- 테스트 먼저: 넉넉·떨어짐, 부분 일치, 같은 이름 변경·삭제, 담기 저장 키 하나만 쓰기.
- 커밋: `feat: point out matching items already at home (F63)`.

### Task 5: 대용량을 다 쓸 때 (F64, AC139·AC140)

- 총량·한 달 사용량을 같은 단위로 받고 다 쓰는 달을 올림한다. 유통기한 개월보다 길 때만 걸리는 점을 보인다. 빈 선택값은 저장하지 않는다.
- 테스트 먼저: 정수·소수 셋째 자리, 10÷1과 10÷2, 기한 경계, 한 칸만 입력, 복원 손상.
- 커밋: `feat: compare bulk use duration with shelf life (F64)`.

### Task 6: 목표가와 본 값 (F65, AC141·AC142)

- 목표가와 수동 관찰 값(날짜·가격, 최대 30건)을 적는다. 같은 날은 마지막 값으로 바꾸고, 마지막 관찰·관찰 중 가장 낮은 값·목표가 이하 여부를 보여 준다. 자동 조회 없음.
- 테스트 먼저: 날짜순과 같은 날, 30건 상한, 목표가 경계, 옛 물건·백업, 상품 링크·캘린더 기존 흐름.
- 커밋: `feat: track a target price and manually seen prices (F65)`.

### Task 7: 반품 기한과 반품 기록 (F66, AC143~AC145)

- 결정 기록의 구매함 카드에서 판매처 기준의 반품 기한을 적고 D-n을 보여 준다. 기한 날짜의 종일 일정은 F35의 이스케이프·75바이트 접기를 재사용하되 VALARM이 없다. ‘반품했어요’는 확인 뒤 날짜를 남긴다.
- 모으기에 반품했다고 적은 등록 가격을 별도 줄로 표시한다. 실제 환불·저축액으로 말하지 않는다.
- 테스트 먼저: D-14/D-0/지난 날짜, 회고 후회 조건, .ics/구글 주소, 반품 확인·되돌리기·저장 손상.
- 커밋: `feat: track return deadlines and returned items (F66)`.

### Task 8: 되팔기 기록과 생긴 돈 (F67, AC146·AC147)

- 회고 후회·그저 그래요인 구매함 카드에 올린 날·판 날·판 금액을 적는다. 판 날·금액은 함께만 받고, 판 날은 올린 날 이후다. 모으기의 ‘생긴 돈’은 옮긴 돈·목표와 구분한다.
- 테스트 먼저: 회고 조건·입력 범위·날짜 순서·수정·되돌리기·예전 백업·모으기 분리.
- 커밋: `feat: record resale and separate proceeds from savings (F67)`.
