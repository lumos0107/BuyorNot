**Goal:** PRD v0.46의 절약·저축 1b(F50 요금 바뀜 기록, F51 같은 곳에 쓰는 구독·멤버십, F52 통신 약정과 요금 비교 링크, F53 수도·가스·전기 요금, F45 보강 주마다·저장 안내 이름, F46 보강 체험 캘린더, F47 보강 해지한 날, F48 보강 요금 낮춤, F20 보강 공과금 백업, AC100~AC116)와 1a에서 넘어온 M8(검사 도우미 한 곳으로)을 만든다. 작업마다 앱이 동작하고 자동 테스트가 모두 통과하는 상태로 끝낸다.

**Architecture:** 고정비는 지금처럼 `Subscription`(키 `buyornot.subscriptions.v1`, `schemaVersion: 1`)에 선택 필드 넷(`intervalWeeks`·`areas`·`contractEndDate`·`priceChanges`)과 결제 주기 값 `'weekly'`만 더한다. 공과금은 새 키 `buyornot.bills.v1`과 새 저장 훅 `useBills`(1a의 `useSavings`와 같은 구조), 계산·문장은 새 `src/logic/bills.ts`, 화면은 새 `src/screens/BillsSection.tsx`(App이 고정비 탭 패널 안, `SubscriptionScreen` 아래에 그린다). 백업은 `backupVersion: 2` 그대로 `bills`를 선택 부분으로 더한다. 요금 바뀜 기록은 수정 폼의 입력(`SubscriptionInput.priceChange`)으로 들어와 `updateSubscription` 안에서 순수 함수 `applyPriceChange`로 기록되므로 `useSubscriptions`는 고치지 않는다. 화면 문장은 지금처럼 `src/logic`의 상수·문장 함수(`fixedCosts.ts`·`bills.ts`·`savings.ts`·`calendar.ts`)에서 만들고 화면은 그 결과만 그린다.

**Tech Stack:** React 19, TypeScript 6, Vite 8, Vitest 5 + Testing Library(jsdom, `renderHook` 포함), Node 24. 1a 계획과 같다. AI 서버(`worker/`)와 `eval/`은 건드리지 않는다.

**Spec:** `PRD.md` v0.46의 F50~F53 절, F45·F46·F47·F48·F20 끝의 2026-11-01 보강, F14·F35 끝의 2026-11-01 보강 줄, 9장 '절약·저축 1b에서 정한 것'과 '정하지 못한 것'의 1b 줄, 11장 AC100~AC116과 고친 AC84. 배경: `docs/superpowers/specs/2026-11-01-saving-features-design.md`(PRD와 다르면 PRD), 총괄 판정 R45~R50(`.superpowers/sdd/saving/decisions.md`, `.superpowers/sdd/2026-11-01-saving-p1a/progress.md`), 1a 전체 리뷰(`.superpowers/sdd/2026-11-01-saving-p1a/final-review.md`). 제작자 판정 칸: `docs/평가/판정표.md` #41~#46.
