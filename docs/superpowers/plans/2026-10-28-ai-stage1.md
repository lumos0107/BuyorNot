# 살까말까 중간 과제 1단계(AI 기능) 구현 계획

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** PRD v0.23의 1단계(F31 가격표 사진으로 온라인 가격 확인, F32 두 상품 사진으로 묶음 비교 채우기, F33 말로 담기, F35 고민 끝나는 날 캘린더)를 저장하지 않는 무료 AI 서버와 함께 만든다.

**Architecture:** 정적 앱(React, GitHub Pages)은 그대로 두고 `worker/`에 Cloudflare Workers 서버를 하나 둔다. 서버는 Gemini 키를 숨기고 Gemini·다나와만 부른다. 앱은 빌드 변수 `VITE_AI_SERVER_URL`이 있을 때만 AI 탭·버튼을 보인다(F35는 늘 보임). 판단이 들어가는 부분(서버의 입력·응답 검사와 다나와 줄 뽑기, 앱의 규격 확인·비교 문장·칸 채우기·.ics)은 순수 함수로 떼어 단위 테스트하고, 화면은 기존 방식(App 통합 테스트 + 모의 fetch)으로 검증한다.

**Tech Stack:** React 19, TypeScript 6, Vite 8, Vitest 5 + Testing Library(jsdom), Cloudflare Workers(wrangler 4.154.0), Gemini API REST v1beta `gemini-3.5-flash-lite`, Node 24(평가 스크립트를 .ts 그대로 실행).

**Spec:** `PRD.md` v0.23 — 10장 "중간 과제 AI 기능 공통", F31, F32, F33, F35, 11장 AC51~AC61. 결정 근거는 `_개인기록/GPT_검토_기록.md` 33~36번(Git 제외).

## Global Constraints

- 화면 문구는 PRD에 적힌 문장 그대로 쓴다. F31 결과에는 '최저가'·'싸요'·'이득'을 쓰지 않는다.
- 저장 형식은 바꾸지 않는다(WishItem 새 필드 없음, `schemaVersion: 1`).
- `VITE_AI_SERVER_URL`이 비어 있으면 AI 탭·버튼을 렌더하지 않는다. 기존 테스트는 고치지 않고 통과해야 한다. F35는 서버 주소와 상관없이 보인다.
- 서버는 요청·응답 본문(사진·녹음·받아쓴 글·읽은 글)을 저장하거나 `console`에 찍지 않는다. 모든 응답에 `Cache-Control: no-store`.
- 서버 값: IP당 60초 10번, 본문 글자 수 상한(JSON을 풀기 전) 사진 4,100,000·녹음 2,100,000·상품 10,000, 요청 전체 55초(다나와 포함, 본문을 다 읽고 해석할 때까지), Gemini 한 번 40초·503일 때만 남은 시간이 15초 이상이면 1번 더, 다나와 조회 1번(리디렉션 포함 HTTP 최대 2번)·10초·받는 동안 3,000,000바이트에서 끊음. 환경 변수 `AI_ENABLED`, `DANAWA_ENABLED`(문자열 `true`일 때만 켜짐, 배포 기본값 `DANAWA_ENABLED=false`).

- 앱이 담기 폼에 값을 넣을 때는 빈 칸만 채운다(F21의 기존 동작은 그대로).
- 색은 `src/index.css`의 변수만 쓰고 그라데이션·이모지는 쓰지 않는다. 아이콘은 Tabler 인라인 SVG. 읽은 글은 글자로만 렌더한다(`dangerouslySetInnerHTML` 금지).
- `worker/test/`의 모든 테스트 파일 첫 줄은 `// @vitest-environment node`이고 `npm test`에 함께 돈다. 서버 코드는 `src/ai/types.ts`를 `import type`으로만 쓴다(이 파일에는 타입만 둔다).
- 테스트의 가짜 전역(MediaRecorder·getUserMedia·createImageBitmap·canvas·URL.createObjectURL)은 `src/test/aiMocks.ts`에만 두고, 테스트마다 `afterEach`에서 `vi.unstubAllGlobals()`·`vi.unstubAllEnvs()`·`vi.useRealTimers()`로 되돌린다.
- `worker/src`의 상대 import는 확장자 `.ts`를 붙인다(`worker/tsconfig.json`에 `allowImportingTsExtensions: true`). 다나와 평가 스크립트가 서버 함수를 Node로 직접 불러 쓰기 때문이다(Task 16, PRD F43).
- 커밋만 하고 push하지 않는다. `_개인기록/`, `PRD_1주안.md`, `worker/.dev.vars`, `.env*.local`은 커밋하지 않는다. 파일은 LF로 쓴다(`.gitattributes`).

- 채점(PRD F43): 값이 있는 칸은 맞음·틀림·못 읽음, 표기 없는 칸은 맞음·채움. 사진은 정답 순서대로 이름 키워드로 AI 상품과 짝짓고, 짝 없는 정답은 값이 있는 칸 못 읽음·표기 없는 칸 맞음, 짝 없는 AI 상품은 '더 읽음'. 다나와는 고른 줄이 모두 허용 줄이고 가장 낮은 가격의 허용 줄을 포함하면 맞음, 허용 줄 밖을 하나라도 고르거나 가장 낮은 허용 줄을 빠뜨리면 틀림, 허용 줄이 있는데 못 고르면 못 읽음, 허용 줄이 없는데 고르면 채움. 429·503(우리 서버)은 `fields: []`로 두고 따로 센다. 그 밖의 실패는 값이 있는 칸 못 읽음, 표기 없는 칸은 `unscored`(분모에서 뺌).
- Produces (`eval/score.ts`):
  - `export type FieldOutcome = 'correct' | 'wrong' | 'missed' | 'blank-ok' | 'filled' | 'unscored'`
  - `export function scoreField(expected: string | null, got: string | null, match?: (expected: string, got: string) => boolean): FieldOutcome`(기본 비교는 같은 문자열)
  - `export function keywordMatch(keywords: string, got: string): boolean`(공백으로 나눈 키워드가 모두 들어 있음)
  - `export function pairByKeywords(expected: string[], got: string[]): { pairs: [number, number][]; extra: number[] }`(정답 순서대로 아직 짝 없는 첫 AI 결과와 짝)
  - `export function scoreDanawa(accepted: number[], picked: number[], prices: number[]): FieldOutcome`(`prices[i-1]`은 줄 i의 가격)
  - `export function failedFields(fields: { field: string; expected: string | null }[]): EvalCase['fields']`(값이 있으면 missed, null이면 unscored)
  - `export type EvalCase = { id: string; httpStatus: number | null; ms: number | null; fields: { field: string; expected: string | null; got: string | null; outcome: FieldOutcome }[]; extra: string[] }`(httpStatus null = 시간 초과·네트워크 오류, 다나와 직접 호출은 성공 200·Gemini 실패 502로 적는다, 429·503 사례는 `fields: []`, `extra`는 더 읽은 상품 이름·표기)
  - `export type EvalResultFile = { date: string; model: string; feature: 'read-tag' | 'lowest-price' | 'voice-fill' | 'read-size'; set: '조정용' | '평가용'; promptVersion: string; cases: EvalCase[] }`. 결과 파일은 기능마다 하나다.
- 결과 JSON에는 위 형식 말고도 사례별 원시 응답을 함께 남긴다(`_개인기록/평가/결과/`에만, 커밋하지 않음).
- 같은 원본에서 잘라 낸 사진·연속 촬영·같은 문장을 다시 녹음한 것·같은 날 같은 검색어의 사본은 조정용과 평가용 중 한쪽에만 둔다(PRD F43 누출 막기).
