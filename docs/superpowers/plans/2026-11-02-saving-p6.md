# 30일 결제 달력과 장보기 초안 구현 계획

**목표:** PRD v0.72 F74~F75(AC172~AC179). 두 기능은 이미 적은 기록을 읽고 새 서버·계정 연결·가격 추측 없이 동작한다. `saving` 브랜치에서 커밋만 한다.

**스킬 적용:** `.claude/skills/simplifying-entry-flows/SKILL.md`에 따라 새 필드를 만들지 않는지, 반복 날짜의 경계가 정확한지, 체크한 초안을 실제 구매로 오해하지 않는지 검토한다. 달력은 고정비의 `nextBillingDate` 규칙을 재사용하고, 장보기는 집에 있는 것의 이름 정리·요리 재료 비교를 재사용한다. 저장 키와 백업 판은 바꾸지 않는다.

### Task 1: 30일 결제 건 계산 (F74, AC172~AC174)

- 오늘~29일 뒤의 반복 결제 건을 매월·매년·주마다·체험 후 첫 결제 규칙에 따라 모두 만든다. 해지한 고정비는 제외하고 각 건에는 저장된 주기 요금을 사용한다.
- 테스트 먼저: 달의 마지막 날·2월 29일, 30일 안 두 번 결제, 주마다, 오늘·29·30일 경계, 체험·해지.
- 커밋: `feat: calculate recurring payments over thirty days (F74)`.

### Task 2: 고정비의 결제 달력 (F74, AC175)

- 고정비 요약 다음에 접힌 결제 달력의 건수·합계, 일곱 열 날짜, 날짜별 목록·포커스를 둔다. 아무 기록이 없을 때의 안내와 360px 가로 넘침을 확인한다.
- 테스트 먼저: 합계는 발생 건마다의 원래 요금, 날짜 버튼 포커스, 빈 상태, 키보드.
- 커밋: `feat: show a thirty-day payment calendar (F74)`.

### Task 3: 장보기 초안 후보 계산 (F75, AC176·AC177)

- 남은 정도가 조금·떨어짐인 집에 있는 것과, 고른 요리의 없는 재료를 이름 정리 규칙으로 합쳐 중복을 없앤다. 넉넉한 항목·고르지 않은 요리는 제외한다.
- 테스트 먼저: 생필품·식재료, 요리 선택, 공백·대소문자 중복, 후보 0개.
- 커밋: `feat: derive a shopping draft from pantry records (F75)`.

### Task 4: 임시 장보기 체크 화면 (F75, AC178·AC179)

- 집에 있는 것 안에 접힌 초안을 두고 요리 한 개를 고르며 항목을 체크할 수 있게 한다. 체크는 화면 상태뿐이고 재고·이벤트·백업에는 쓰지 않는다. 새로고침 뒤에는 체크가 사라진다.
- 테스트 먼저: 체크 후 접고 다시 열기, 새로고침, 재고 불변, 빈 상태, 360px.
- 커밋: `feat: add a temporary shopping checklist (F75)`.
