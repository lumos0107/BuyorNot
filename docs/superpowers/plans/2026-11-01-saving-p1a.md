> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** PRD v0.44의 절약·저축 1a(F45 고정비 정리함, F46 무료 체험 끝나는 날, F47 해지했어요, F48 모으기, F49 주요 메뉴 다섯 개, F20 보강 백업 v2, AC81~AC99)를 만든다. 작업마다 앱이 동작하고 자동 테스트가 모두 통과하는 상태로 끝낸다.

**Architecture:** 고정비는 기존 구독 기록(`Subscription`, 키 `buyornot.subscriptions.v1`)에 선택 필드 셋(`kind`·`trialEndDate`·`cancelledOn`)만 더한다. 계산과 문장은 `src/logic/subscriptions.ts`(저장 모양·결제일·요약)와 새 `src/logic/fixedCosts.ts`(종류·체험·해지 문장)에 둔다. 모으기는 새 키 `buyornot.savings.v1`(`{ schemaVersion: 1, transfers, goal }`)와 새 저장 훅 `useSavings`(기존 `useSubscriptions`와 같은 여러 탭·손상 규칙), 계산·문장은 새 `src/logic/savings.ts`, 화면은 새 `src/screens/SavingsScreen.tsx`. 줄어든 고정비·참은 구매는 저장하지 않고 볼 때마다 계산한다. 백업은 `backupVersion: 2`로 모으기를 더하고 v1도 받는다. 화면 문장은 지금처럼 logic의 상수·문장 함수에서 만들고 화면은 그 결과만 그린다.

**Tech Stack:** React 19, TypeScript 6, Vite 8, Vitest 5 + Testing Library(jsdom, `renderHook` 포함), Node 24. 2회차 계획과 같다. AI 서버(`worker/`)와 `eval/`은 건드리지 않는다.

**Spec:** `PRD.md` v0.44의 F45~F49 절, F20의 2026-11-01 보강, F12·F14·F17·F18 끝의 2026-11-01 보강 줄, 9장 '절약·저축 1a에서 정한 것', 11장 AC81~AC99. 배경: `docs/superpowers/specs/2026-11-01-saving-features-design.md`(2026-11-01 고친 판, PRD와 다르면 PRD), 총괄 판정 R45·R46(`.superpowers/sdd/saving/decisions.md`). 제작자 판정 칸: `docs/평가/판정표.md` #35~#40.

**브랜치:** `saving`(`ai-stage1` 908be29에서 갈라짐). 병합 순서 `ai-stage1` → main → `saving`은 제작자 몫이다.

## Global Constraints

- PRD v0.44의 새 문장과 동작은 모두 'Claude 결정, 제작자 확인 전'이다. 작업을 시작하기 전에 `docs/평가/판정표.md`에서 그 작업의 줄(Task 1·4 #35, Task 5 #36, Task 6 #37, Task 3·7 #38, Task 3 #39, Task 2 #40)을 본다. 제작자가 '아니오'나 '바꿈'으로 적었으면 코드보다 PRD를 먼저 고치고(updating-prd) 이 계획의 문장도 바꾼다. 빈칸이면 PRD v0.44 문장대로 만든다.
- 화면 문구는 PRD에 적힌 문장 그대로 쓴다(따옴표 안 글자, `·`, `‘ ’`, 마침표, 띄어쓰기까지). 어디서도 사라·말라를 말하지 않고, 줄어든 고정비·참은 구매를 저축액처럼 말하지 않는다. 세 숫자를 더한 값은 어디에도 그리지 않는다. 문구를 바꾼 작업은 checking-ui-copy 스킬로 점검한다(스크립트 + PRD 대조 + 빠진 문장).
- 조사는 `josa()`·`withJosa()`(`src/logic/number.ts`). 이름 뒤 "을/를"은 늘 `josa(name, '을/를')`.
- 색은 `src/index.css`의 변수(`--accent` 등)만 쓴다. 새 색·그라데이션 없음. 진행 막대는 `<progress>`와 `accent-color: var(--accent)`.
- 저장은 더하기만 한다. `buyornot.subscriptions.v1`은 `schemaVersion: 1` 그대로이고 새 필드는 모두 선택이다. 예전 기록(새 필드 없음)과 예시 구독 5개는 그대로 읽히고 결과가 같다(AC27·AC30·AC31 등 기존 테스트를 고치지 않고 통과). `kind`가 구독이면 저장하지 않아, 예전 입력으로 만든 기록의 모양이 바뀌지 않는다. 백업 v1 파일은 계속 읽힌다.
- 기존 저장 훅은 기존 동작을 바꾸지 않는다. `useSubscriptions`에는 Task 6의 `cancel`·`resume` 두 동작만 더한다(설계 4장 #23의 2026-11-01 고친 줄). `useWishlist`·`useSettings`는 고치지 않는다.
- 한 번 누름은 저장 키 하나만 쓴다(해지는 고정비 키, 옮긴 돈·목표는 모으기 키). 백업 불러오기만 예외(F20 그대로).
- 새 예시 데이터를 넣지 않는다(AC30 그대로, R46).
- 테스트 이름은 한국어 문장이고 **맨 앞에 검증 번호**를 붙인다(예: `'AC86: 체험이 끝난 다음 날부터는 결제일 규칙으로 다음 결제일을 잡는다'`). 기대 문장은 PRD에서 복사한다(writing-tests-from-spec). 오늘 날짜는 `vi.useFakeTimers({ now: … , toFake: ['Date'] })` 또는 각 파일의 기존 시계 방식을 따른다.
- 가짜 전역은 `src/test/aiMocks.ts`의 것만 쓴다(이 계획은 새 가짜 전역이 필요 없다). `localStorage`는 jsdom의 것을 쓰고 `beforeEach`에서 `localStorage.clear()`. 저장 실패는 기존 테스트처럼 `vi.spyOn(Storage.prototype, 'setItem')`으로 그 키에서만 던지게 하고 `afterEach`에서 `vi.restoreAllMocks()`.
- 기존 테스트는 고치지 않는 것이 기본이다. PRD v0.44가 기대값을 바꾼 곳만 작업에 적힌 대로 고치고 커밋 메시지 본문에 그 AC와 개수를 적는다(Task 2 `backup.test.ts` 3곳, Task 3 탭 이름, Task 4 고정비 화면 문장).
