# 절약·저축 4단계 구현 계획

**목표:** PRD v0.61 F68~F71·F20 보강(AC151~AC162). 모으기 맨 아래 접힌 ‘받을 수 있는 돈’에 제도 확인·카드 실적·포인트 만료·정산을 둔다. `saving` 브랜치에서 커밋만 한다.

**공통:** 새 키 `buyornot.benefits.v1`, schemaVersion 1. 백업 판 3은 유지하고 새 파일에는 `benefits`를 넣는다. 판 1·2·옛 판 3에 이 부분이 없으면 현재 기록을 유지한다. 손상된 부분이 있으면 전체 백업을 거절한다. 다른 탭이 먼저 쓴 기록을 덮지 않고, 화면 반영이 확인된 경우에만 입력을 비우거나 성공 안내를 보인다. 폼은 제목을 눌러 여는 작은 영역으로 두어 모으기 화면 길이를 억제한다. 전화번호·계좌번호는 입력받지 않는다.

### Task 1: 저장과 백업 (F68~F71·F20, AC162)

- 프로그램·카드·만료·정산 데이터의 복원 검사, 각 최대 개수, 날짜·금액·이름 범위를 `logic/benefits.ts`에 둔다. `useBenefits`에는 다른 탭·저장 실패 처리를 둔다.
- `backup.ts`, `App`, `BackupSection`에 새 키를 연결한다. 새 판 3은 포함, 옛 판 3은 누락 허용·현재 값 유지. `benefits`가 있으면 반드시 검증한다.
- 테스트 먼저: 저장 왕복·손상 거절·상한·옛 백업 세 판과 새 판 왕복·다른 탭 덮어쓰기 방지.
- 커밋: `feat: persist benefits and include them in backups (F20, F68-F71)`.

### Task 2: 공식 링크와 직접 확인 (F68, AC151~AC153)

- 공식 링크 세 개는 2026-11-02 확인한 고정 목록이다. 공식 페이지에서만 조건을 확인하게 하고 자격 판정·금액 예측을 하지 않는다. 목록이 180일 지나면 날짜 경고를 보인다.
- 항목마다 확인한 날·상태, 받는 중이면 받은 금액 선택 입력. 모으기의 ‘생긴 돈’에 직접 적은 받은 금액을 별도 합계로 보이되 옮긴 돈·목표와 더하지 않는다.
- 테스트 먼저: 링크 호스트·새 창·입력 전송 없음, 상태 저장, 금액 구분, 오래된 목록 경계.
- 커밋: `feat: track official benefit checks without eligibility guesses (F68)`.

### Task 3: 카드 실적 (F69, AC154·AC155)

- 카드 이름·월·기준·쓴 금액·혜택을 직접 입력하고 차이만 보여 준다. 지난달은 월을 표시한다. 초과 소비를 권하는 문장은 없다.
- 테스트 먼저: 기준보다 2만 원 부족·같음·초과, 지난달, 상한·삭제, 저장 실패.
- 커밋: `feat: show manually entered card spending gaps (F69)`.

### Task 4: 포인트·쿠폰 만료 (F70, AC156~AC158)

- 만료일 오름차순·D-n·지난 날짜, 종일 .ics·구글 캘린더(VALARM 없음). 금액은 모으기 합계에 넣지 않는다.
- 테스트 먼저: 정렬·D-0·지난 날짜, .ics 날짜·VALARM 없음, 상한·삭제.
- 커밋: `feat: track point and coupon expiry dates (F70)`.

### Task 5: 친구 정산·빌려준 돈 (F71, AC159~AC161)

- 별명·방향·금액·날짜를 적고 받을 돈과 줄 돈 합계를 따로 보인다. 받았어요·줬어요는 정산한 날만 남긴다. 받은 돈을 모으기에 넣지 않는다.
- 테스트 먼저: 두 방향 합계·정산 뒤 제외·백업 별명·범위·저장 실패.
- 커밋: `feat: track personal settlements separately from savings (F71)`.
