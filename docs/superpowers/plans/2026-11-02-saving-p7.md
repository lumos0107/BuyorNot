# 절약 행동 연결 25~27단계

제작자 요청: “전부다 수행해보자”(2026-11-02). 대상은 직전 제안의 여섯 기능이다. `saving`에서 커밋만 하고 push하지 않는다.

## 25단계 · 식재료와 정기배송 (F76~F77)

1. T1: 기존 한 끼 선택을 유지하면서 이번 주 요리 3개까지 고르고 부족한 재료를 장보기 초안에 한 번씩 합친다. 선택은 화면에서만 유지한다.
2. T2: 집에 넉넉한 생필품과 같은 이름의 활성 정기배송이 7일 안에 오면 확인 문장을 보인다. 배송을 앱이 변경하지 않는다.

## 26단계 · 작은 지출과 구매 결정 (F78~F79)

3. T3: 이미 적은 자잘한 지출에서 지난 7일과 이번 7일의 횟수를 비교하고 한 번 덜 쓰기 목표를 표시한다. 기록이 없으면 수치를 만들지 않는다.
4. T4: 사기 전 카드 맨 위에 가격·중복·할부·사용 빈도·목표가의 적힌 근거를 요약한다. 자세한 입력은 기존처럼 아래에 둔다.

## 27단계 · 고정비와 시작 동선 (F80~F81)

5. T5: 7일 안에 결제할 활성 구독·멤버십에 최근 사용 기록을 확인하고 유지·해지 판단으로 이어지는 한 줄을 보인다. 다른 고정비에는 일반 결제 확인만 보인다.
6. T6: 첫 화면에 물건 고민·장보기·고정비 세 시작 버튼을 두고 목적 화면의 제목으로 포커스를 옮긴다.

## 28단계 · 한 주 시도 선택 보강 (F78)

7. T7: 지출 버튼 하나를 한 주 시도로 선택·저장하고 시작 때의 기준 횟수와 7일 진행·완료를 보인다. 옛 저장값과 백업 호환, 버튼 삭제·선택 변경·여러 탭을 확인한다.

각 단계는 PRD AC를 테스트로 먼저 옮긴 뒤 구현한다. 관련 테스트, 전체 테스트, lint, tsc, 빌드, 360px 화면을 확인한다. 단계 완료마다 TODO·DEVLOG·GPT 진행기록과 화면 확인 목록을 적는다. 실제 스마트폰 확인은 제작자 몫으로 남긴다.
