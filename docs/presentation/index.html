시연 1 · 구매 전

담아 두고, 고민하게 하고, 다시 묻는다

  • 문제 담아 두고 기다리기만 하면 다시 볼 이유가 약하다
  • 조작 담을 때 갖고 싶은 정도(1~5), 앱을 연 날마다 "오늘의 고민" — 정도를 다시 고르고 남은 질문 하나에 답한다
  • 결과 "담을 때 4 → 3 → 2 (2 줄었어요)" — 날짜가 다른 기록만 판정한다. 구매함을 누르면 정도 변화 · 걸리는 점 · 그 밖에 답한 것
  • 의미 충동구매라고 단정하지 않고, 내 기록과 마음의 변화를 보고 스스로 정한다

시연: 예시 물건 넣기 → 헤드폰의 오늘의 고민 → 구매함(걸리는 점 2개) → 구매 포기 → 되돌리기

시연 2 · 구매할 때 · 할인 비교

15% 할인 vs 8,000원 할인

문제: 할인율이 높아도 최대 할인액과 배송비를 보면 결제액이 달라진다

조건A안B안
상품 금액80,000원80,000원
쿠폰15% (최대 10,000원)정액 8,000원
배송비3,000원0원
결제액73,000원72,000원

B안이 1,000원 저렴해요 — 80,000 × 15% = 12,000 → 최대 할인 10,000 → 80,000 − 10,000 + 3,000

최소 주문액 미달이면 "적용 불가 · 1,000원 부족"처럼 이유를 함께 보여준다

시연 3 · 구매할 때 · 묶음 · 무료배송

900mL × 2개 vs 1.5L × 1개

문제: 대용량은 단가가 낮아도 오늘 쓰는 돈은 더 많을 수 있다

상품 A상품 B
가격6,000원5,400원
총량1,800mL1,500mL
100mL당333.33원360.00원

상품 A가 단가 7.4% 낮아요. 총지출은 A가 600원 더 커요 — 가격만 비교한 결과예요

무료배송 채우기: 8,000원 더 담으면 배송비 3,000원 줄고 총지출 5,000원 늘어요 — 사라고 하지 않고 총지출을 함께 보여 준다

시연 4 · 구매 후

산 뒤에도, 구독도 돌아본다

  • 결정 기록: 구매 포기 금액(아낀 돈이라 부르지 않음), 시급을 넣으면 몇 시간어치인지
  • "고민하는 동안 갖고 싶은 정도가 줄어든 물건 2개 중 2개를 안 샀어요" — 기록된 변화와 결정만 보여 준다

바이브 코딩에서 겪은 일 1

테스트가 잡은 버그: "총지출이 큰 쪽"을 거꾸로 표시

무슨 일이

AI가 쓴 결과 문구가 "총지출이 더 큰 쪽"을 단가 판정에서 유추했다. A 2,000원·B 1,500원인데 "상품 B가 500원 더 커요".

다른 값을 넣은 화면 테스트가 처음 잡았고, AC10 예시 화면에서도 잘못 표시될 오류였다. 예시 테스트는 단가 줄만 확인하고 있었다.

어떻게 고쳤나

계산 로직에 spendMore(총지출이 큰 쪽)를 따로 두고, 로직 테스트 2건을 먼저 보강해 실패를 확인한 뒤 구현.

교훈: 단가와 총지출은 별개의 사실. 로직이 직접 답하게 하고, 테스트는 예시 값 말고 다른 값도 넣는다.

바이브 코딩에서 겪은 일 2

GPT 검토가 잡은 크래시, 그리고 직접 확인한 지적

묶음 개수에 아주 큰 수를 넣으면 화면이 깨짐

검증을 통과한 Infinity가 BigInt 변환에서 RangeError. 개수 9,999개·용량 1,000만 상한을 두고 총량을 BigInt로 계산.

0.0004g처럼 아주 작은 용량이 총량 0이 되던 문제도 같은 검토에서 → 소수 셋째 자리까지만 받도록

"표시 동률" 판정이 화면과 어긋난다

GPT: Math.round(1.005×100)은 100인데 화면은 "1.01". 바로 믿지 않고 Node로 직접 실행해 확인한 뒤, 화면과 같은 포맷 함수로 판정하도록 수정.

반대로 "색 토큰이 8개"라는 지적은 색상(hue)은 4개라고 근거를 들어 반영하지 않았다.

방법론의 장단점

빠르지만, 검증 없이는 믿을 수 없다

좋았던 점

  • 화면 뼈대와 배포·테스트 설정이 한 단계에 나왔다 (커밋 시각 기준 17분)
  • 테스트를 먼저 쓰게 하면 AI 코드의 오류를 그 자리에서 잡는다
  • 두 AI가 역할을 나누니 서로의 실수를 짚는다 (검토 지적 133건)
  • 검증 사례를 테스트로 옮기면 계획서 모순도 드러난다 (AC21·AC27)
  • 요청·결과·수정 이유가 DEVLOG에 그대로 남는다

조심할 점

  • 규칙 해석 실수(총지출 방향, 큰 값): 사람이 숫자로 확인해야 한다
  • 요청하지 않은 것을 만들 수 있어 TODO에 '하지 않을 것'을 적었다
  • 도구 문제에 시간이 든다: 가짜 타이머 멈춤, Codex 샌드박스 오류
  • 검토 의견도 틀릴 수 있어 직접 실행해 보고 정했다
  • 포커스 같은 접근성은 자주 빠진다: 7~11단계 검토 지적 28건 중 8건
