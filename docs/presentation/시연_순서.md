# 살까말까 발표 순서 (5분)

발표 화면: [README](../../README.md)(GitHub 저장소 첫 화면)와 웹사이트 https://lumos0107.github.io/BuyorNot/ 두 탭. 웹사이트는 스마트폰 또는 PC 브라우저의 모바일 보기(360px)로 연다. [옛 HTML 슬라이드](index.html)는 4차 시점 자료라 이번 발표에는 쓰지 않는다.

준비: 웹사이트의 사이트 데이터를 지워 빈 상태에서 시작한다. 예시 데이터는 모두 "(예시)"가 붙은 가짜 데이터라고 처음에 한 번 말한다.

## 서비스 시연 (2분)

1. **충동구매 다시 생각하기 (50초):** 첫 화면에서 **예시 물건 넣기**를 누른다. 담기 폼이 "(예시) 전기 포트"와 체크리스트까지 채워진다. 아래 "(예시) 무선 헤드폰" 카드에서 "체크리스트 6/6"과 "담을 때 4 → 3 → 2 (2단계 줄었어요)"를 보여준다. ★ 시간이 되면 **구매함** → "사기 전에 한 번 더 · 걸리는 점 3개"를 3초 보여 주고 **취소**한다.
2. **할인 쿠폰 비교 (25초):** **가격 비교** 메뉴. 할인 비교는 처음부터 예시가 채워져 있다. A안 73,000원, B안 72,000원, "A안의 할인율이 더 높아도, 배송비까지 더하면 B안이 1,000원 저렴해요".
3. **가성비 비교 (20초):** **묶음상품 비교** 탭. 100mL당 333.33원과 360.00원, "100mL당 가격은 상품 A가 낮지만, 총지출은 상품 B가 600원 적어요".
4. **구독 정리 (25초):** **구독** 메뉴 → **예시 구독 넣기**. 월 46,280원, "해지 후보 1개 · 월평균 10,900원"(음악 스트리밍, 마지막 사용 40일 전). 사용 시간·횟수는 직접 적은 값으로 1시간·1번당 얼마인지 계산한다고 말한다(웹사이트는 스크린 타임을 읽을 수 없음).

말조심: 결정 기록의 금액이나 "갖고 싶은 정도가 줄어든 물건 …" 문장은 예시 데이터로 계산한 값이다. 실제 효과처럼 말하지 않는다.

## 막혔을 때

- 배포 링크가 안 열리면: `npm run build && npm run preview` 후 http://localhost:4173/BuyorNot/
- 예시 데이터가 이미 있으면: 제목 아래 **예시만 지우기**(구독은 **예시 구독만 지우기**)로 지우거나 브라우저 사이트 데이터 삭제
- 화면이 PC 폭이면: 개발자 도구(F12) → 기기 툴바에서 360px로
- 카카오톡 같은 앱 안의 브라우저로 열면 기본 브라우저와 기록이 따로 저장된다. 시연은 같은 브라우저에서 한다.
- 날짜에 따라 D-n과 "n일 전"은 달라진다. 예시 데이터는 넣는 날을 기준으로 만들어지므로 순서와 상태, 갖고 싶은 정도의 변화는 같다.

## 부록: 기능별 자세한 시연 (질문이 나오거나 시간이 남을 때)

아래는 4차까지 쓰던 6분짜리 시연 순서다. 흐름은 소비 시점 순서다: **구매 전** → **구매할 때** → **구매 후**.

### 1. 구매 전 — 고민 목록 · 고민 노트 · 사기 전 점검 (2분)

문제: "사고 싶은 순간에 바로 결제하기 쉽고, 담아 두고 기다리기만 하면 다시 들어올 이유가 약해요."

1. 첫 화면에서 **예시 물건 넣기**를 누른다. → 담기 폼이 "(예시) 전기 포트"와 펼친 "체크리스트 (선택) · 6/6"까지 채워지고, 아래에 고민 중인 예시 2개("(예시) 무선 헤드폰", "(예시) 접이식 건조대")가 같은 모양으로 들어간다. ★ **담아 두기**를 누르면 폼의 체크리스트 답이 카드에 "체크리스트 6/6"으로 들어간다.
2. 예시 줄 아래 "오늘 갖고 싶은 정도를 안 적은 물건 2개"의 **적으러 가기** → "(예시) 무선 헤드폰" 카드의 **오늘의 고민**으로 내려간다("앱을 열면 오늘 적을 곳을 바로 찾아 줘요"). → "담을 때 4 → 3 → 2 (2단계 줄었어요)"와 질문 6개 체크리스트(질문 아래 답, 잘못 누른 답은 다시 답하기). 예시에는 며칠에 걸친 기록(담은 날 4, 3일 전 3, 2일 전 2)이 들어 있다고 말한다. 같은 날 바꾼 값은 판정하지 않는다.
3. ★ "(예시) 접이식 건조대" 카드에서 오늘 정도 **2**를 누른다. → "담을 때 3 → 3 → 2 (1단계 줄었어요)". 체크리스트의 "빌리거나 중고로 대신할 수 있나요?" 줄에서 **다시 답하기** → 그 질문이 펼쳐지면 **어려워요**. → 다시 "체크리스트 6/6".
4. 헤드폰 카드에서 **구매함**을 누른다. → "사기 전에 한 번 더 · 걸리는 점 3개"(남은 고민 기간 포함), 바로 아래 "갖고 싶은 정도: 담을 때 4 → 3 → 2 (2단계 줄었어요)", 그 밖에 답한 것(없으면 생기는 문제, 대신하기 어려워요 등). **취소**한다.
5. **구매 포기**를 누르고 메모에 "쓰던 유선 이어폰을 고쳐 씀"을 적은 뒤 **구매 포기 확인**. → 제목 아래 "‘(예시) 무선 헤드폰’을 구매 포기로 옮겼어요. 되돌리기".
6. ★ **되돌리기**를 누르면 카드가 돌아온다. 다시 구매 포기한다.

의미: "충동구매라고 단정하지 않아요. 내 기록과, 고민하는 동안 마음이 어떻게 바뀌었는지를 보여 주고 결정은 제가 해요. 고민 기간 중에는 구매함을 강조하지 않고 '일찍 정할 수도 있어요'라고만 적어요."

### 2. 구매할 때 — 할인 · 묶음 · 무료배송 비교 (1분 40초)

1. **가격 비교** 메뉴 → 할인 비교 탭에서 **예시 넣기**.
   - 문제: "할인율이 높아도 최대 할인액과 배송비를 보면 결제액이 달라져요."
   - 결과: A안 73,000원, B안 72,000원, "B안이 1,000원 저렴해요". 계산 근거를 한 줄 읽는다.
   - ★ **B안으로 담기** → 고민 중인 물건으로 넘어가 가격 72000과 이유 "가격 비교: B안 결제액 72,000원 (할인 8,000원 · 배송비 포함)"이 채워지고 상품명에 커서가 간다. 이 비교 문장 속 "할인"은 사기 전 점검의 할인 근거로 세지 않는다고 말한다. 다시 가격 비교로 돌아온다.
2. 묶음상품 비교 탭에서 **예시 넣기**.
   - 문제: "대용량은 단가가 낮아도 오늘 쓰는 돈은 더 많을 수 있어요."
   - 결과: 100mL당 333.33원 vs 360.00원, "상품 A의 단가가 7.4% 더 낮아요", "단가는 상품 A가 낮지만, 총지출은 상품 B가 600원 적어요".
3. 무료배송 채우기 탭에서 **예시 넣기**.
   - 문제: "배송비를 아끼려고 더 담으면 전체 지출은 늘어날 수 있어요."
   - 결과: 지금 30,000원 → 추가한 뒤 35,000원, 총지출 차이 +5,000원, "배송비는 3,000원 줄고, 총지출은 5,000원 늘어요".

의미: "광고 문구보다 실제 지출을 비교해요. 단가가 낮다고, 무료배송이 된다고 사라고 하지 않고 총지출을 같이 보여 줘요."

### 3. 구매 후 — 결정 기록 · 구독 (1분 40초)

1. **결정 기록** 메뉴.
   - 문제: "산 뒤에 잘 샀는지, 고민한 게 도움이 됐는지 모르고 지나가요."
   - 결과: 요약 "구매 포기 2건 278,000원"과 "실제로 아낀 돈과는 다를 수 있어요", "갖고 싶은 정도가 줄어든 물건 2개 · 그중 안 산 물건 2개". 헤드폰 카드에 "갖고 싶은 정도: 담을 때 4 → 3 → 2 (2단계 줄었어요)".
   - 시급 칸에 **10000** → "입력한 시급으로 환산하면 약 27.8시간".
   - "(예시) 무선 청소기"(9일 전 구매) 카드의 "잘 샀나요?"에서 **후회해요 → 회고 저장** → 요약에 "회고 1건 중 후회 1건".
   - **고민 중인 물건** 메뉴 → 담기 폼 상품명을 지우고 **로봇 청소기** 입력 → 상품명 아래 알림 "9일 전에 '(예시) 무선 청소기'를 구매했어요 · 회고: 후회해요". 다시 결정 기록으로 돌아온다.
   - 말할 것: "산 뒤에 남긴 회고가 다음에 비슷한 물건을 담을 때와 사기 직전 점검에 다시 나와요. 이름이 비슷하다는 사실만 보여 주고, 이번에도 후회할 거라고 단정하지 않아요."
   - 말할 것: "효과 문장은 기록된 변화와 결정을 보여 줄 뿐, 고민 때문에 줄었다고 단정하지 않아요."
2. **구독** 메뉴 → **예시 구독 넣기**.
   - 문제: "가입한 구독과 실제로 쓰는 구독을 구분하기 어려워요."
   - 결과: 월평균 구독료 46,280원, 연 555,360원, "해지 후보 1개 · 월평균 10,900원"(음악 스트리밍, 마지막 사용 40일 전). "(예시) 쿠팡 와우 멤버십"은 "사용량(예시): 최근 30일 1번 사용 · 1번에 약 7,890원꼴".
   - "(예시) 음악 스트리밍"의 **오늘 썼어요** → 마지막 사용이 오늘이 되고 해지 후보에서 빠지며 "사용량(직접 기록)"으로 바뀐다.
   - ★ "(예시) 배달의민족 배민클럽"의 **사용량 적기** → 사용 횟수 **4** → **저장** → "사용량(10/17에 적음): 최근 30일 4번 사용 · 1번에 약 1,000원꼴". 배달 횟수는 주문 내역을 보고 한 달에 한 번 적는다고 말한다.
   - 말할 것: "자동으로 사용 시간을 모으는 게 아니라 직접 적거나 기록해요. 웹사이트는 휴대폰 스크린 타임을 읽을 수 없어요. 사용 기록이 없는 구독은 해지 후보가 아니라 '확인 필요'로 보여요."

### 4. 마무리 (40초)

- ★ 화면 맨 아래 **기록 백업·복원**을 펼쳐 백업 파일 받기를 보여준다(서버 없이 기록을 옮기는 방법).
- GitHub 저장소의 커밋 목록과 Actions 배포 기록을 한 번 보여준다.
- 결론: "살까말까는 구매를 대신 결정하지 않아요. 필요성, 실제 지출, 사용 기록을 확인하도록 도와요. 이번에는 기능의 동작과 계산을 검증했고, 앞으로 실제 사용자에게 입력이 번거롭지 않은지, 구매 판단에 도움이 되는지 확인하고 싶어요."
